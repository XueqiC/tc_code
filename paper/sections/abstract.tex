Deploying a large language-model agent often means distilling it into a small
model that serves one task domain, specified only by a handful of example
queries. Two requirements decide whether the student is deployable: knowing
which requests fall inside the domain, and training a student whose
competence ends where the domain ends. Both are usually approached with
semantic similarity, which cannot succeed when two tasks share their surface
text but differ in the skills they require. We represent both requirements in
one space. The gradient that a trajectory induces at the student's
initialization encodes what learning that task would change, and a sparse
dictionary over these gradients yields capability atoms: interpretable units
that support task boundaries, capability prediction, and data selection in a
single representation. On a hard pair sharing identical questions but
differing in action space (Python versus chain-of-thought), gradient
boundaries reach AUROC $1.000$ where trajectory embeddings reach $0.687$
(pilot). Atom support resolves within-domain skills (SQL-join, AUROC
$0.906{\pm}0.025$) where dense subspaces fail ($0.615$). Boundaries carry
finite-sample conformal coverage guarantees and are stable across nine
reference models from 0.8B to 27B parameters. Under matched token budgets,
boundary-guided selection ties the best in-domain execution accuracy while
removing out-of-domain capability most strongly, and a refusal variant
separates in-domain from out-of-domain requests at 100\% versus 0\% refusal
rates (pilot). We also report a pre-registered capability-proxy gate that
failed, and the mechanism analysis that replaced the proxy.
