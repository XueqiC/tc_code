\section{Introduction}

Language-model agents that act by writing and executing code are moving from
research demonstrations into production systems, where they operate tools,
query databases, and automate multi-step workflows
\citep{trivedi2024appworld, yao2024taubench}. Serving a frontier model for
every such workload is rarely economical, and practice is converging on a
standard remedy: distill the teacher's behavior on one task domain into a
small, specialized student \citep{kang2025distilling, tang2026smartad}. The
task domain itself is usually specified informally, by a handful of example
queries that a deployment team collects from the intended workload.

Deploying such a student raises two questions that current distillation
practice does not answer. First, given a new request, does it fall inside
the domain the student was built for? Second, does the student's competence
in fact coincide with that domain, covering neither less of it nor more than
intended? Existing agent-distillation methods optimize aggregate benchmark
scores \citep{kang2025distilling, tang2026smartad} and provide neither a
boundary predictor nor a capability guarantee. We call the joint problem
\emph{distill-to-specification}: from a teacher and $k$ example queries,
produce a boundary predictor with a coverage guarantee together with a
student whose measured capability matches the specified domain on both sides.

The natural tool for both questions is semantic similarity over request
text, and it fails for a structural reason rather than an empirical one.
Consider the same arithmetic word problem solved twice, once as an executable
Python function and once as chain-of-thought prose. The two requests are
identical strings, so no function of the request text can distinguish them.
They nevertheless define different tasks: the two solutions exercise
different skills, and a student distilled for one does not acquire the other
(Section~\ref{sec:boundary}). Task identity resides in what a model would
have to learn, not in what the request says.

We therefore represent tasks by their learning demands. The gradient that a
teacher trajectory for query $q$ induces at the student's initialization
records which parameters must change for the student to learn that
trajectory; a low-rank adapter sketch makes this representation practical at
one backward pass per example \citep{hu2022lora, xia2024less}. A sparse
dictionary learned over trajectory-block gradients then factors these demands
into \emph{capability atoms}, recurring directions that align with
recognizable skills: the atoms that separate join queries from other SQL
activate precisely on \texttt{JOIN} clauses. One representation supports the
full pipeline. A task specification is the atom support of the $k$ example
queries, equipped with a split-conformal acceptance threshold that carries a
finite-sample coverage guarantee \citep{vovk2005algorithmic,
gibbs2025conditional}. A student's capability is predicted from the supply
each atom receives from its training data, in the spirit of gradient-based
attribution \citep{park2023trak, rosser2026gradient}, and is validated
against execution outcomes. Data selection fills a token budget with the
trajectories that supply the specified atoms.

Our contributions are as follows.
\begin{itemize}[left=0pt,itemsep=0pt]

\item \textbf{Problem formulation.} We formalize
\emph{distill-to-specification}: from a teacher agent and $k$ example
queries, produce a boundary predictor with a finite-sample coverage
guarantee together with a student whose measured capability matches the
specified domain on both sides, evaluated as a coverage--leakage frontier
under matched token budgets across student sizes
(Section~\ref{sec:setting}). To our knowledge, no prior agent-distillation
work provides either component.
\item \textbf{Key insights.} Task identity is recoverable from learning
dynamics where it is provably invisible to surface semantics: gradient
boundaries separate identical-query hard pairs at AUROC $1.000$ versus
$0.687$ for trajectory embeddings, saturate at $k{=}5$ examples while
embedding boundaries degrade with larger $k$, and reproduce across nine
reference models from 0.8B to 27B parameters. Capability removal during
narrow distillation operates by supply starvation rather than gradient
conflict, which makes leakage controllable at selection time
(Sections~\ref{sec:boundary},~\ref{sec:distill}).
\item \textbf{Method.} Capability atoms: a sparse dictionary over
trajectory-block gradients that serves as the single representation for
boundary estimation (atom support with conformal calibration), forward
capability prediction (atom supply, validated against execution outcomes
after a pre-registered gate rejected post-hoc gradient-norm proxies), and
budget-constrained data selection with an optional refusal module
(Section~\ref{sec:method}).
\item \textbf{Performance.} At pilot scale, atom support resolves
within-domain skills at AUROC $0.906{\pm}0.025$ where dense subspaces reach
$0.615$; boundary-guided selection ties the best in-domain execution
accuracy (90\%) while removing out-of-domain capability most strongly among
budget-matched baselines, and the refusal variant separates in-domain from
out-of-domain requests at 100\% versus 0\% refusal rates. Multi-seed
(size, budget) sweeps and agent-environment evaluations are in progress and
will replace pilot figures in this cycle
(Sections~\ref{sec:atoms},~\ref{sec:distill}).

\end{itemize}
