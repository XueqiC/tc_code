# 调研笔记:蒸馏中 in-task 与 off-task 能力的耦合与解耦

(2026-08-21 深夜;大故事线:budget 被尽可能用来提升 in-task performance,
泄漏 = 预算漏损。)

## 一、文献图景

**1. 任务向量与干扰子空间。** Task arithmetic(Ilharco et al. 2023)把
微调增量当向量做加减;后续工作发现任务向量重叠时产生知识冲突,
2025-26 的一批方法(KnOTS、TSV、Iso-C/Iso-CTS)都在**奇异子空间层面**
去重叠:白化、拉平奇异谱、分离共享/专属方向。含义:耦合在参数增量的
**共享低秩方向**上,解耦 = 让各任务的更新占据近正交子空间。我们的
capability atom 就是这个对象的"字典版"——而且我们在**买数据时**就
控制它,不是训完后再修。

**2. 灾难性遗忘与"表观遗忘"。** 窄语料微调伤一般能力是老现象;新解释
(Revisiting CF in LLM Tuning 等)指出部分遗忘是**任务对齐被扰乱**而非
能力被抹除——权重里知识还在,输出分布被格式/风格拉走了。这正是我们
AppWorld 风格捕获的机制(base 规划能力还在,克隆把行为拉走),也解释
为什么 19 条自解行(replay 锚)就能救回:锚恢复的是对齐,不是重学能力。

**3. Replay/锚定。** 持续学习的少量 replay 防遗忘、self-distillation
bridging distribution gap(混少量学生自产数据缩小分布差)——与我们
"学生自身分布必须在训练分布中有锚"的三次跨域观察一致。

**4. 对我们的定位。** 文献处理的是"训练后如何修复耦合伤害"或"多任务
如何共存";我们的独特角度是**采购时的预算几何**:泄漏不是训练副作用,
是买错了东西——钱流向了 off-task 也能用的原子。这个视角文献里没有。

## 二、我们自己的证据(实证)

**已有判定(重读)**:
- 零泄漏的机制是**环内门 + 回购**(同一购单去门残留 .900;仅加权 .700;
  基线 .93-1.00)→ 泄漏由**数据内容**决定,且可在题面层面拦截;
- 开门的 in-task 代价 ≈ 0(.642 vs .645)→ 在 gsm/sqljoin 这对任务上,
  in-task 与 off-task **不是此消彼长的权衡,而是可以同时优化的两个轴**
  ——界外数据对 in-task 没有正贡献(否则关门会掉分);
- 松弛频谱 s≤1.0 残留仍 0.000 → 边界附近有"安全带",两任务的题面
  分布在梯度特征空间里分得很开。

**联合字典重叠谱(coupling_study.py,数字见 results/coupling_study.json)**:
64 个活跃原子:**gsm 专属 42、join 专属 20、共享仅 2**。
gsm 需求落在共享原子上的质量 **2.2%**,join 侧 **4.1%**;那 2 个共享
原子内部双方质量比 ~0.74-0.77(真共享,不是噪声)。
**读数**:这对任务在原子空间近乎正交(κ ≈ 2-4%)——于是基线 .40-.77
的巨额泄漏**不可能来自共享原子**,只能来自"直接买了界外数据";
配额的 min(·) 截断天然把共享原子的采购封顶在 ~2% 需求,题面门再拦
掉界外题——零泄漏 + 开门代价 ≈0 就同时被解释了:**在低 κ 任务对上,
in-task 与 off-task 不是权衡,是两个独立的会计科目**。H-C1 的前提
成立;H-C2(高 κ 对,如 gsm-code×gsm-cot)成为下一个关键测试。

**跨域损失谱(免费挖掘,9 个 run 的 Δloss vs base;负 = 获得能力)**:

| 目标域 | boot3 | selfinst | ourscorr | 读数 |
|---|---|---|---|---|
| gsm-code(主) | -.571 | -.577 | -.543 | 目标能力 |
| **gsm-cot** | **+.174** | +.151 | +.184 | **干扰:能力被摧毁**(base any_acc .5 → 0,100% 改写代码) |
| pandas | -.157 | -.266 | -.326 | **正迁移**:共享 python 原子,能力顺带提升 |
| sql | -.094 | **+.183** | +.222 | 近正交:boot3 中性,基线反而伤它 |
| alpaca | -.211 | -.234 | -.236 | 轻度正迁移(格式) |

**耦合三分型**(比"泄漏"更精细的图景):
- **解耦**(sql:双视图 κ 都低)→ 门保零残留,互不影响;
- **建设性耦合**(pandas:响应视图 κ 高,同为 python)→ 正迁移,数据
  选择拦不住也不该拦;
- **破坏性耦合**(cot:题面视图 κ≈1 而响应风格冲突)→ 训练一种风格
  摧毁另一种——这就是 AppWorld 风格捕获的受控版本!
**精化假设 H-C4:耦合的符号由响应视图原子重叠决定,暴露程度由题面
视图重叠决定** ——而双视图字典恰好免费给出这两个 κ:我们的字典设计
天然是"耦合预报器",这是单视图方法没有的能力,故事直接升级。

## 三、耦合的工作模型(可检验)

把任务 T 的能力写成原子需求向量 w_T。两任务的耦合度
κ(T,T') = Σ_a min(w_T,a, w_T',a)(需求重叠质量)。假设:
- **H-C1**:无约束采购(selfinst 等)的 off-task 泄漏随 κ 单调增加;
  κ 小的任务对(gsm vs sqljoin)泄漏也大(实测 .40-.77),说明基线的
  泄漏主要来自**买了界外数据**而非共享原子——配额 min(·) 截断 +
  题面门足以归零。
- **H-C2**:κ 大的任务对(如 gsm-code vs gsm-cot)上,零泄漏不可能
  仅靠数据选择达成——共享原子的训练必然双向提升;此时"纯度"的正确
  定义要改为"超出共享底座的专属能力不泄漏"。
- **H-C3(设计)**:字典学习加**组稀疏/对比结构**(atom 按"in-task
  专属 vs 参照共享"分组)可以在**花钱之前**预测一笔采购的泄漏贡献:
  leak̂(x) = Σ_{a∈shared} c_a(x)·tokens。若 leak̂ 与实测残留相关,
  就得到"预算漏损预测器"——大故事线的定量武器。

**双视图 κ 谱(3 任务对实测,GPU2)**:

| 对 gsm-code | 题面视图 κ(共享原子数) | 响应视图 κ(共享原子数) | 实测 ΔL |
|---|---|---|---|
| sqljoin | .230(52) | **0.000(0)** | ≈0(解耦) |
| pandas | .145(48) | .0002(1) | -.16~-.33(建设性) |
| gsm-cot | **.756(63)** | .013(**16**,cot 侧 31% 需求) | +.15~.18(破坏性) |

**H-C4 判定:部分成立,且修正后更漂亮**——两个视图测的是两件事:
- **题面 κ = 可混淆度**:解释基线为什么泄漏(sql 题面 κ .23,基线才会
  买 sql 数据)、门为什么必须在题面视图工作(拦的恰是可混淆度);
- **响应 κ = 干扰潜力**:cot 是唯一响应视图显著共享的对(16 原子,
  cot 侧 31% 需求压在共享原子上)且风格冲突 → 破坏性;sql 响应 κ=0
  → 买漏了也只是浪费钱,不伤能力;
- **修正**:建设性迁移(pandas)不经过任务级共享原子(仅 1 个)——
  它走"底座层"(python 语法流利度),低于原子分辨率,拦不住、
  无害、免费。原子词汇刻画的是任务级技能;底座迁移是蒸馏的免费
  副产品,这反而支持"配额不需要也不应该管它"。
**一句话**:题面 κ 决定门要挡多少,响应 κ 决定训练会伤谁,底座迁移
是白送的——三个量里前两个都由我们的双视图字典在花钱前免费给出。

## 三之二、理论化方向(off-task = in-task 优化的自然延伸,可推导)

目标形态:一个**可推导的耦合定律**,实验双重验证。候选推导路径——
把训练增量近似为所购数据梯度的加权和 Δθ ≈ Σ_x η·g(x),g(x) 在字典
上分解 g(x) ≈ Σ_a c_a(x)·d_a,则 off-task T' 的损失变化一阶近似为
ΔL_{T'} ≈ -η·Σ_a S_a·⟨d_a, ∇L_{T'}⟩,其中 S_a = Σ_x c_a(x) 是采购
在原子 a 上的总供给。于是:
- **解耦对**:∀a, S_a>0 ⇒ ⟨d_a, ∇L_{T'}⟩≈0(采购只落在 T' 不用的
  原子)→ ΔL_{T'} ≈ 0(实测 sql:-.09,≈0 ✓);
- **建设性对**:共享原子上 ⟨d_a, ∇L_{T'}⟩>0 → ΔL_{T'}<0,收益
  ∝ 共享供给质量(实测 pandas -.16~-.33 ✓);
- **破坏性对**:题面重叠但响应方向相反,⟨d_a^{resp}, ∇L_{T'}⟩<0 →
  ΔL_{T'}>0,且损伤 ∝ 供给(实测 cot +.15~+.18 ✓)。
**定量预测(可检验)**:ΔL_{T'} 应与 Σ_a S_a·κ_a^{±}(T,T')(带符号
的原子级耦合供给)线性相关——三对任务已给三个点,预算曲线(2k-40k)
给出同一对内的供给扫描:若 ΔL_cot 随预算线性恶化、ΔL_pandas 随预算
线性改善、ΔL_sql 恒平,定律成立。tc-coup 的预算格恰好提供这条曲线,
锚探针则检验"在供给里加入 T' 方向的分量可中和破坏项"。

## 四、方法与故事的落点

1. **解释现有结果**:我们又高又纯,是因为预算只为 in-task 需求的原子
   付钱(min(·) 截断限购共享/无关原子),门再把漏网的题面拦掉——
   "budget 全部转化为 in-task 能力"不是口号,是原子空间的会计恒等式。
2. **升级 capability atom(候选,待验证)**:双视图字典再加一块
   **参照语料对比项**(通用语料在 atom 上的编码作为"共享度"标签),
   atom 天生携带 专属/共享 标记 → 采购目标从"覆盖需求"精化为"覆盖
   专属需求、限购共享需求";泄漏可以在采购前逐笔预测。
3. **论文叙事**:Section 5 加一小节 "The geometry of leakage":重叠谱
   图 + 漏损预测器相关性 + 门开关对照,把纯度从"结果"升级为"机制"。
