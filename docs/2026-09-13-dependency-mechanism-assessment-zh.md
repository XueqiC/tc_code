# 对"保留交互依赖的局部教学 + 递归注意力"新机制的评估 — 2026-09-13

评估依据:今天(9/12)在 BFCL 上跑完的 R1/R2 全部数据、三项实现核查、以及正在 LONI 上跑的修复后四种子配对实验。
结论先说:**第一阶段值得做,而且是目前最该做的实验;第二阶段的设计是对的,但我预期它在 BFCL 上大概率出空结果,理由见 §4。**
我提三处修改,都来自今天量到的具体数字。

## 1. 这套设计相对今天的做法,好在哪里
今天真正被否掉的不是"靶向练习无效",而是我们**没能把两件事分开**:训练有没有正确学到交互边界,以及练习里到底有没有学生必须自己作的决策。
新设计把第一阶段的自变量收敛成"**训练上下文是否保留了学生原本必须承担的选择**",这正好切中今天暴露的问题:
- 终止监督缺陷(已修)说明我们对"交互边界"的监督本身就是残缺的;
- R2 的练习全部是"给定正确前缀 → 补全一个调用",教师强制下 base 已经在 96% 的位置给出教师 token,
  这组数字**不能**用来推断自主执行时的能力(已撤回该推断),但它确实和"练习可能太容易"这一待检验解释相符。

评测顺序也改对了:把**自主完成短交互的成功率**放在第一位,246 题开发集降为第三位。今天的数据支持这个降级——
该集合上单训练种子波动 ±8 题(R1:D 先领先 8 题,换种子反被领先 8 题,两种子均值 0),而且它已被反复使用。

不训练先做起点检查(§3)这一步尤其正确:它只花推理,却能在投入 adapter 之前判断练习是否保留了原困难。

## 2. 三处我建议修改(依据今天的数字)

### 2.1 第一轮就加入"等长连续片段"对照臂 L,不要等 P 赢了再补
I 与 P 之间其实差两件事:**前置信息是给定的还是自己取的**(目标变量),以及**监督序列是否跨越多个相互依赖的动作**(长度/结构混杂)。
方案把等长对照放在 P 胜出之后,但今天在 LONI 上我们已经验证:**9 个臂完全并行时墙钟与 1 个臂相同**(每臂一个 run 目录,45–75 分钟训练 + 45–60 分钟评测)。
所以把 4 个 adapter 扩到 6 个(I/P/L × 2 配对种子)**不增加任何等待时间**,却能在第一轮就排除长度混杂。代价只是机时,额度尚余约 46k SU。

### 2.2 教学素材的父任务数才是统计瓶颈,不是包数
现有 support 24 题中,**只有 5 题被诊断出失败**(memory_kv ×2、live_parallel ×1、multi_turn ×2),而 R2 的 64 条练习实际只来自 **5 个不同父任务**。
如果第一阶段仍按"诊断出的失败"取素材,24–32 个教学包依然压在 5 个来源上,而方案自己也写明"同一教学包拆出的练习仍算一个来源"。

**建议放宽取材条件:I/P 对照不需要学生原本失败,只需要任务本身存在真实的信息依赖。**
按这个条件,support 里可用的多步任务有 **9 个**(memory_kv ×2、multi_turn_base ×2、long_context ×2、miss_func ×2、miss_param ×1),
比 5 个提高近一倍,且覆盖四类多步结构。这不改变 support 规模(仍是冻结的 24 题),只是不再把取材限制在失败案例上。

### 2.3 确认集要先确认"可造性",再谈 32 个父任务
方案要求新的确认集起步 32 个独立父任务、每题两个合法环境变体,且变体必须由环境初始化产生真实事实差异。
今天的实际产出是:R2 的确认集从 16 题 calibration 里只生成了 **16 项 / 8 个有效配对**。
另外 R1 生成时 45 个候选里有 **18 个因"执行器快照不可用"被拒**(R2 加入多轮快照重建后这一项已大幅改善,但仍非 100%)。
所以 32 父任务 × 2 变体 = 64 项是**上限而非起点**,我会先用 8 个父任务试产,量出成品率再决定规模,并把"变体是否真的改变了正确动作"作为硬校验(和现有 `condition_action_changes` 同一套检查)。

## 3. 立即可做且很便宜的一步:起点检查(不训练)
从 9 个多步 support 任务里取 4–6 个可回放的依赖案例,每个比较三种起点,学生自主生成完整动作、工具返回真实 observation:

| 起点 | 检查目的 |
|---|---|
| 原任务中关键选择前的状态 | 学生原本的错误是什么 |
| 现有独立局部练习(R2 的 condition/surface 变体) | 是否已经把困难选择提示或代办了 |
| 新的依赖保留练习 | 缩短任务后,原困难是否仍然存在 |

期望看到的现象:学生能完成"已告知报告位置后的复制",但从原始需求出发不会主动去找位置,而新短链练习能重现这一困难。
**若三种起点没有这个差异,就先改练习构造,不训练 adapter。** 这一步只需要一张 GPU 跑推理,几小时内出结果。

## 4. 对第二阶段(递归注意力)的判断:设计对,但我预期在 BFCL 上出空结果
三个读取对照(一次读取 / 正确 support 两次读取 / 错配 support 两次读取)设计得很好,**错配对照是真正的证伪器**。
但方案自己点出的风险在 BFCL 上很可能成立:**题目陈述加工具说明可能已经完全决定了该取什么证据**,于是选择器无事可做,正确 support 与错配 support 不会有差别。
支持这一担心的今天证据:base 在开发集上已经做对 65%,诊断出的缺口很窄(archival 检索、并行调用单位),都是"读了工具说明就该知道"的类型。
所以我建议:**第二阶段只跑三个读取对照的检索指标(必要证据遗漏率、相关证据覆盖率、无关上下文比例),不训练、不购买**;
只有出现增量才进入购买与训练。这与方案一致,我只是把"预期为空"写在前面,免得空结果被当成实现问题。

## 5. 必须守住的实现要求(今天踩过的坑)
1. **两臂等价性硬检查**:把 I/P 的实际训练样本渲染出来,逐条标注"I 中哪些前置条件是文本给定的、P 中哪些必须通过交互取得";
   若两臂每个监督 token 的前缀/目标/mask/权重完全一致,则实验退化为同一目标,**不跑**。
2. **曝光匹配用工具量,不用配置声明**:`exposure-audit` 现在能分开报告内容 token 与三类边界 token。
   今天的实测:修复后内容 token 曝光 15,850,与修复前**完全相同**,边界监督是额外的 590 个 token——
   所以"剂量被改变"这一替代解释可以被排除,这个工具在新实验里同样必须每臂都跑。
3. **剂量冻结**:沿用修复后 C/D 四种子验证过的配置(正在跑);不同时搜索新 loss、新门控或多套学习率,不按确认集挑中点 checkpoint。
4. **并行结构**:每臂一个 run 目录。今天 9 个作业共用一个目录被一把 flock 全局串行,1.5 小时只训完 1 个臂。
5. **统计**:先按父任务聚合再配对;同时列出每个训练种子的差异;多变体、多种子都不等于更多独立任务。
6. **两个种子只用于筛选**;方向一致再补到四个。今天已经证明单种子会给出方向相反的结论。

## 6. 我的执行顺序
1. **现在**:LONI 上修复后的 C/D 四种子跑完(用于判断原练习协议与训练稳定性,并冻结剂量);GPU4 上开始 §3 的起点检查(纯推理)。
2. **起点检查通过后**:构造同源 I/P(+L)教学包,渲染差异审计,4–6 个依赖父任务起步,目标 24–32 个包。
3. **训练**:I/P/L × 2 配对种子 = 6 个 adapter,LONI 并行,一晚出结果;主指标按"自主局部交互 → 条件变化适应 → 完整任务与损伤"顺序读。
4. **达到判读表中的"P 稳定改善且完整任务同向"才进入第二阶段**;否则按表处理,不扩 benchmark。
5. Table 1 的 27 格在机制实验让出节点后重排,不与本线争配额。

## 7. 一句话总结
这套设计把今天最有价值的收获(把"学没学到交互边界"和"练习里有没有真决策"分开)变成了可执行的实验,第一阶段值得全力做。
我会加一个等长对照臂、把取材从"诊断失败"放宽到"存在信息依赖"以缓解父任务稀缺、并先用小规模试产确认集的成品率。
第二阶段按原计划只做检索指标的廉价对照,我预期为空,但那本身也是一个干净的结论。
