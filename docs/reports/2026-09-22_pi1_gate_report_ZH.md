## 3. 根因(当晚定位,证据完整)

### 3.1 失效方式:模型不收手,不是选错

吃满 40 步的局从 base 的 55 涨到 69–90。翻开逐回合记录,机制很直接:

```
executed 'look'  but the reply names admissible 'open cabinet 1'
generated_text: 'THOUGHT: I should open cabinet 1 ...\nACTION: open cabinet 1<turn|><turn|><turn|>thought
                 \n<channel|>ACTION: open cabinet 1<turn|><turn|><turn|>thought\n<channel|>ACTION: ...'
```

模型**说对了**(命名了合法动作),但回复**永不终止**:不断吐 `<turn|>` / `<channel|>` 并重复 ACTION,
直到 256 token 上限。解析器因此取不到干净的命令,**静默回退成 `look`**,智能体原地不动、烧光步数。

### 3.2 量化(4,169 个回合 vs base 3,491 个回合)

| 指标 | base | 3 遍 seed0 |
|---|---:|---:|
| **"回复里有合法 ACTION,却执行了 `look`"** | **2.3%** | **15.2%** |
| `look` 执行率 | 16.7% | 20.6% |
| 回复以 EOS 正常结束 | 3.4% | **1.0%** |
| 首行本身就是合法命令 | — | **0/1169 = 0%** |

**判别量是第一行:base 同样有 98% 的 `<turn|>` 污染却只有 2.3% 误解析;
训练后的模型把 ACTION 重复多次并夹杂标记,误解析涨到 15.2%,是 base 的 6.6 倍。**

### 3.3 根因:监督目标缺少原生回合边界

```
D0 supervised targets, how they end:
  no explicit boundary: 424 / 424
example target (last 80 chars):
  "...I'll check sidetable 1 first.\nACTION: go to sidetable 1"
```

**424 个监督目标全部以裸动作文本结尾,没有任何回合边界 / EOS。**
模型被教会"产出 ReAct 回合",**但从未被教会在哪里停**。

**这一条正是用户 09-21 任务书 §3 明确要求过的**:
「新数据包含教师实际生成的 Thought、Action **和原生回合边界**」。**这个边界没进目标,这是采集/渲染侧的忠实性缺口。**

### 3.4 为什么这解释了全部现象

- 不终止 → 重复 ACTION + 标记 → 解析失败率 6.6× → `look` 空转 → 吃满 40 步 → 分数塌。
- **剂量单调向好(−23.07 → −11.07)**:曝光越多,格式越稳,误解析越少,分数越回升——
  与"崩塌带"表现一致,但**成因不是词汇,是终止**。
- **不需要重新采购**:教师完整回复已经存在银行里,边界是**渲染训练行时**该补的 token。**改训练侧即可。**
