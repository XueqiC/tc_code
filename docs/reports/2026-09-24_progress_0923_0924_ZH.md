## 1. 09-23 上午：第二轮机制实验收尾

### 1.1 做了什么、怎么做的
在同一个 87 条已验证教师轨迹的池（32 个支持任务，每任务最多 3 次尝试）上，固定配方（纯 CE、LoRA r16、AdamW 1e-5、96,490 监督 token ≈ D0 的 10 遍），
只改变"训练用哪些轨迹"，在 mike / rai / hpg 三台机器上各评 3 个训练 seed：

- **四格**（材料 × 目标）：A = D0（每任务首次成功的 30 条）纯 CE；B = D0 任务等权；C = 全部 87 条纯 CE；D = 87 条任务等权。
- **材料拆分臂**：ALT1 = 每任务换成池里 id 最大的另一条（仍是 30 条）；1min = id 最小的另一条；PER2 = 每任务 2 条（59 条）。
- **诊断臂 MIX1**：ALT1 的选材只把 4 个 heat 任务换成 1min 的那条（用了评测类型信息，只作诊断）。
- **原版 baseline**（按各自论文口径）：SmartAD、SAD、Kang，以及修正版 SmartAD / SAD 作为消融。
- **hpg B200 统一重评**：hpg 在 08:36 恢复，搭了评测树（vLLM 0.27.1，transformers 钉 5.14.1），把 47 个 adapter 推过去统一评。

### 1.2 结果
| 臂 | mike | rai | hpg |
|---|---|---|---|
| base（重复评测：mike 3 次、rai 2 次、hpg 3 次） | 81.3 | 82.5 | 81.0 |
| A：D0 纯 CE | 77.7 | 75.0 | 78.0 |
| **ALT1**：换一批轨迹，仍 30 条 | **86.7** | **87.0** | **86.0** |
| C：87 条纯 CE（全池） | 82.3 | 82.3 | 84.0 |
| PER2：每任务 2 条 | 83.7 | 84.0 | — |
| 1min：另一种任意挑法 | 78 | 77 / 85 / 83 | 79 / 85 / 72 |
| 原版 SmartAD | 82.7 | 81.3 | 81.0 |
| 原版 SAD | 78.3 | 76.0 | 75.7 |
| Kang | 81.0 | 76.7 | 79.0 |

- 任务等权不是普适因子（B−A：rai +5、mike 0；D−C ≈ 0）。
- "87 条比 30 条好"不是数量效应：同样 30 条换一批轨迹就拿到全部增益，固定预算下 1 条/任务 ≥ 2 条 ≥ 3 条。
- MIX1 = 86 / 90，但 heat 本身没变（5.0 = ALT1），增益在材料完全相同的类型上 → 读作 seed 噪声，诊断关闭。
- **跨机器噪声**：同一份 1min s2 权重，rai 83、hpg 72（12 局只在 rai 成功，全是 hpg 上 40 步耗尽）；5 个检查点两台机器合计 423 vs 422，没有系统偏置，但脆弱的检查点能差 11 局。

## 2. 09-23 下午到夜里：方法线（跨任务学习收益选材料，TVD）

### 2.1 做了什么、怎么做的（按你 13:13 的计划）
1. **候选集**：每任务一条轨迹，3 个随机（rnd1/2/3）+ 1 个 NLL 选择（nll1 = SmartAD 的最低 token-NLL）+ 两个锚点（1alt、1min）；夜里又加了第 7 个"全池"（让方法可以直接返回全池 SFT，和最强 baseline 正面比）。
2. **支持集内部验证**：32 个支持任务按类型分 4 折（每折 8 题，种子 4242）；每个候选 × 每折，用其余 3 折训练（同一 96,490 终点，并在 28,947 = 3 遍存 checkpoint），
   在留出的 8 题上跑 agent，**cv 分 = 4 折留出成功数之和（0–32）**。整个选择过程只碰这 32 个支持任务。
3. **最终模型**：每个候选在全部 32 题上训练，hpg 训练、hpg 评测，2 个 seed；另在 rai 上训 seed 0 作第二训练平台复验；每个最终模型的 3 遍 checkpoint 也都评了。
4. **判读规则在出任何 cv 分之前写死**（方法文档 §3.1，09-23 16:13 提交）：Spearman 精确置换 p ≤ 0.05 且选中集不差于随机和 nll1 → ADVANCE；ρ > 0 → DIRECTIONAL；否则 NO_RELATION。

### 2.2 工程上做的（让 70+ 个作业能在 hpg 上正确跑完）
- 抓到 20 份 cv 配置的 `training_seeds` 与注册配方不符（会在排队 3 小时后全部失败），原地修；nll1 的最终成绩原以为可借用修正版 SmartAD，核对后发现三处不同，单独补训。
- hpg 上**从没跑过训练**：在登录节点上用作业同一命令跑了全部 32 个 preflight；修掉两个悬空的银行软链接。
- 部门账户排不上的原因：**内存额度**（每作业申请 120G，实测训练只用 3 GB）和 **CPU 额度**（申请 14 核，实测 1 核）→ 降到 32G / 4 核（先用小作业验证 `CpusPerTask` 才真正生效）；GPU 上限（24 张）满后写了自动搬运，往组账户挪（最多占 4 张）。
- rai 打分链：合并 → 起服务 → 32 题 rollout → 删合并模型，约 16 分钟一个；调度器等 hpg 打出 TRAIN_DONE 才拉权重；修了我自己引入的标记目录 bug 和误杀打分子进程的问题。
- hpg SSH 主连接断过一次（约 1.5 小时没发现）→ 观察器加了断线告警。

### 2.3 结果
**预登记判读（6 个候选，hpg 训练 + hpg 评测，s0 / s1）**

| 候选 | cv 分（10 遍） | 最终 | 均值 | cv 分（3 遍） | 3 遍最终 |
|---|---|---|---|---|---|
| 1min | **23** | 73 / 81 | 77.0 | 18 | — |
| nll1 | 22 | 81 / 84 | 82.5 | 18 | — |
| 1alt | 21 | 83 / 90 | **86.5** | 19 | 72（s0） |
| rnd3 | 21 | 82 / 81 | 81.5 | 17 | — |
| rnd2 | 20 | 76 / 75 | 75.5 | 16 | 69 / 71 |
| rnd1 | 19 | 85 / 87 | 86.0 | 18 | 66 / 65 |

- **Spearman −0.174（p = 0.64）→ NO_RELATION**；cv 挑中 1min，遗憾 9.5 局；四折排序一致性 Kendall W = 0.16（p = 0.55）。
- 随机集之间 SD 5.3 > seed SD 3.3：材料确实有影响，但 32 个支持任务的 cv 分辨不出来（事先写明的分辨率风险）。
- **剂量方向 6/6 判对**（每个候选 3 遍的 cv 都低于 10 遍）；把 3 遍配置也算进来（目前 8 个有最终成绩）Spearman **+0.49**。
- 零成本对手"银行更短"（固定 token 下 = 每条多看几遍）与最终成绩 **+0.71（p = 0.068）**，又指向剂量。
- rai 训练的 seed 0 最终：1alt 88 / rnd1 88 / rnd2 87 / nll1 79 / 1min 77 / rnd3 77；**同一 rnd2 在 hpg 训练是 76 / 75**，训练平台或 seed 能让同一选材差 ~11 局，大于选材之间的差异。
- 选材的 NLL（初始学生）：nll1 1.78 → 82.5；其余 1.91–1.94，和最终无关 → 按拟合度选"不比随机好"。
