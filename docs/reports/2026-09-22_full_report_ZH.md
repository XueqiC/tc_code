## 3. 起点门失败的根因链与两处修复(已在 token 层面验证)

### 3.1 缺陷
1. **推理停止契约**:gemma-4 的回合结束是 `<turn|>` = id 106(chat template 以其收尾,
   `generation_config.eos_token_id = [1, 106, 50]`),而两个后端只在 `<eos>` = 1 停。base 在 97.7% 的回合里
   ACTION 之后紧跟 `<turn|>`,训练后 99.9%——**模型几乎每次都正确收尾,是后端不认**,于是继续生成
   `<turn|><turn|>thought\n<channel|>…`,产生"重复 ACTION"(v1 记录 97–100% 回合)与失控续写。
2. **训练 labels**:`pi1.encode_teacher_turn` 只监督教师文本,不追加任何边界 id。

### 3.2 修复
- 后端:两后端停止集 = tokenizer eos ∪ `generation_config.eos_token_id`,第一个命中处停;`truncated` = 未以
  原生停止 id 结束。harness 重新冻结为 v2;185 个测试通过。
- labels:追加 `<turn|>`(从 tokenizer special 取 id,非字面量)。preflight 实样本末尾 label 解码
  `": go to diningtable 1<turn|>"`,id 106 在 labels 且未 mask;监督 token 9,225 → **9,649**(+424,每遍都加),
  终点 **28,947 / 96,490**,步数 3 遍 55 / 10 遍 184 不变(按 512 token/更新)。小批执行检查:loss 1.91 有限,
  每行 1 个边界位置参与 loss;base 对该位置 `<turn|>` 的 NLL 仅 1e-6 ~ 3e-4。

### 3.3 两组对照(裁定要求分别记)
**第一组:同一 checkpoint,旧停止 → 原生停止(推理缺陷损失),逐题配对**

| 模型 | v1(旧停止) | v2(原生停止) | 差 | 不一致题(v1 独胜 / v2 独胜) | McNemar p |
|---|---|---|---|---|---|
| base | 85/140 | 79/140 | −4.29 | 16(11 / 5) | 0.21 |
| CE s0 3遍 | 50 | 67 | **+12.14** | 27(5 / 22) | 0.0015 |
| CE s0 10遍 | 68 | 79 | **+7.86** | 15(2 / 13) | 0.0074 |
| CE s1 3遍 | 55 | 72 | **+12.14** | 29(6 / 23) | 0.0023 |
| CE s1 10遍 | 71 | 77 | +4.29 | 20(7 / 13) | 0.26 |

推理修复对训练模型的恢复量 +4 ~ +12 pp(三格显著),对 base 反而 −4.29(不显著)。**旧配置下的"−23 pp 起点门失败"
主要是后端缺陷**;修复后训练模型的"重复 ACTION"从 97–100% 降到 **0.0%**,原生结束率 98–100%。

**第二组:同一停止配置,旧 labels → 修复 labels(训练边界增量),从 base 重训,同 seed / 顺序 / 优化器**

| 终点 | seed | 旧 labels | 修复 labels | 差 | 不一致题 | McNemar p |
|---|---|---|---|---|---|---|
| 3 遍 | 0 | 67 | 68 | +0.71 | 11(5 / 6) | 1 |
| 3 遍 | 1 | 72 | 68 | −2.86 | 16(10 / 6) | 0.45 |
| 10 遍 | 0 | 79 | 80 | +0.71 | 17(8 / 9) | 1 |
| 10 遍 | 1 | 77 | 77 | 0.00 | 12(6 / 6) | 1 |

**训练边界增量在两个终点上都 ≈ 0**(四格 p ≥ 0.45,方向不一致),与 base 对该位置 `<turn|>` 的 NLL 仅 1e-6 ~ 3e-4 一致:模型本来就几乎必然预测该 token,监督它不改变行为。labels 修复保留(训练目标与部署契约一致),但它不是行为损失的来源。

### 3.4 措辞
按用户要求:**"发现边界缺陷,并已验证其行为影响"**。推理缺陷解释了旧配置下下降的大部分;训练侧边界在 base
本就几乎必然预测该 token 的情况下增量很小。**撤回**:"模型没有学会收尾"、"训练模型误解析 15.2% vs base 2.3%"
(后者是失控续写的假象;真实解析器记录的 fallback:base 8.5%,训练模型 5–9%,主因 `candidate_not_admissible`,
属策略层面而非格式)。

cool 仍 −16,clean 始终受益。** 六格共享同一 140 题,"6/6"是跨 seed/方法的方向一致性,不是六个独立样本;单格按类均不显著。

**行为机制(表 §L,看局 + 量化)**
- **cool 掉分 = 被放大的顺序扫描**:训练后模型逐个 `go to cabinet k / open cabinet k`,扫完柜子扫抽屉直到 40 步,而物品在台面上。
  base 在 13/25 局拿到物品(首次 take 平均第 17.6 步),训练后只有 5–8/25 局拿到(拿到时很早,第 6–9 步,否则永远拿不到);
  扫描类动作占比 base 65.9% → 训练后 82.9–89.3%(3 遍 87.4%)。
- **clean 涨分 = 学会了缺失的子技能**:base 不洗就放、随后 look/take/move 循环;训练后插入 `clean X with sinkbasin 1`,步数 28.4 → 23.6–25.1。
- 扫描占比在所有类型都上升 10–20 pp。教师 demo 的扫描占比按类型 13–60%,cool 的 5 条 demo 里 4 条直奔台面(第 2–4 步 take),
  只有 1 条(Plate-Cabinet-7)是 33 步柜子扫描 → **学生把枚举模式放大到超过 demo 中的频率**(易学的 n-gram 式模式压过"先看台面"的先验)。
- 覆盖不是原因:support 分层 look 3 / pick&place 7 / clean 6 / cool 5 / heat 4 / two 7,D0 的 5 条 cool demo 全部已验证入库。

**含义**:三个方法持平不是"没学到",而是都从同一批 demo 学到同一个搜索习惯,得失相抵;方法之间的差异(选择、课程、前缀)
不改变材料本身携带的内容。要高于 base,材料必须针对 base 缺的子技能(clean 的洗、流程类的步骤),而不是整条轨迹的搜索过程。

这也解释了它为何只比纯 CE 高出噪声内的 +0.7~+2.1。

## 9A. 方法雏形与框架(按今晚证据起草,数字见 §5.4;写于 __T9A__)

**一句话**:在预算受限的黑盒教师蒸馏里,收益由"买到什么材料、留下哪条轨迹"决定,而不是由损失函数决定——方法应当是一个**采购与选材算法**,训练侧保持普通 CE 与固定的更新预算。
**门槛**:按论文口径修正后的 SmartAD(逐回合均值 NLL 选例 + 除权重和归一)在 mike 三 seed 88/89/82 = 86.3,比 base 均值高 5.0 pp、cool 不掉——它只改了"选哪条轨迹",
是今晚最强的臂;方法必须可分辨地高于它(≈86),而不是高于 base(≈81)。

**证据链(全部同平台、逐题配对)**
1. 同一批 30 条示范上,普通 CE / SmartAD / SAD / Kang 互相分不开,且都在 base 附近(§5);差异全在类型层面(clean +11、cool −16),由示范里的"柜子扫描"习惯被放大造成(§5.1),害处随高扫描示范走(§5.2)。
2. 把材料换成 87 条(每任务 3 条不同轨迹)、更新次数不变:比 30 条高 +6~+8 题(rai:A 75.0 → C 82.3 / D 81.0;mike:A 77.7 → C 82.3 / D 83.0)(mike / rai 两平台一致);任务等权目标在 30 条上无增益(B ≈ A ;rai 三 seed B 80.0 vs A 75.0 = +5,但 B 单 seed 77/78/85 波动大),在 87 条上与普通 CE 持平(D ≈ C ;rai D vs C 同 seed −1,mike D vs C +1.4(p=0.84))。
3. 87 条比 30 条好,是"更多"还是"不同"?— **是"不同"**:同规模换轨迹的 ALT1 两 seed 86/87 vs A 79/78(§5.4.6);2 条/任务 86;固定预算下更多示范只稀释剂量。材料因子 = 每任务用哪条轨迹。
4. 学生状态纠错(REPAIR)在 40 步 ALFWorld 上产出极低(34 次接管 14 次验证、9 条可用),同预算下 ADD-DEMO 拿到 20 条;mike 三 seed:ADD-DEMO ALL 79.3 ≥ REPAIR ALL 78.3,都不高于 base 81.3,也低于 87 条示范的 C(82.3)——按判定规则"学生状态纠错"不成立,纠错只作框架里的可选件(§5.4.2)。

**框架(候选方法 = 预算内的示范采购与选择)**
- **输入**:K 个支持任务、每任务可购买的教师轨迹上限、学生 π0、总教师 token 预算 B。
- **采购策略**:对每个任务采多条独立轨迹(温度采样,attempt 独立),验证成功才入库(失败计费);优先给 base 失败率高的任务类型追加(clean/heat/cool/two),
  达到"每类型 ≥ m 条可用"后停止——覆盖子技能缺口,而不是均匀撒。
- **选材/过滤**:丢弃"环境探索占比"高的轨迹(扫描柜子/抽屉 > 0.5),保留直接达成目标的轨迹;每任务保留多条不同轨迹(多样性);
  当需要在候选间取舍时用**逐回合均值 NLL**(SmartAD 修正版的统计量,它带来 +2~+5),而不是全 token 均值;两者的组合(多样性 + 逐回合均值选例 + 扫描过滤)是待验证的候选。
- **训练**:普通 CE,观测 mask,原生回合边界,固定的监督 token 预算(与对照同更新次数),不引入 KL/权重。
- **判定**:整体自主成功率的逐题配对 + 三 seed;类型分解作机制证据;unseen 冻结集确认。
- **与基线的关系**:SmartAD(按 NLL 选 1 条)、SAD(分段损失 + 课程)、Kang(前缀续写)都在"给定材料"上做文章;本方法改变的是材料本身,基线在同材料上互相分不开正说明杠杆在采购侧。
