你是本项目的研究工程 coding agent。请核查仓库现状，开发并验证下面的 RTD 统一替换实验分支。目标是获得一个以蒸馏机制为中心、数学对象与代码一致、能提高小模型 agent 完整任务表现的新方法。不要把这项任务缩减为改写论文故事，也不要把旧 RTD 的结果重新命名为新方案的证据。

## 0. 目标、授权边界与交付方式

给定目标任务的 few-shot support set S、黑盒大模型 teacher agent、教师输出 token 预算 B，并具有训练任务环境/结果验证器，我们要蒸馏小模型骨干，使使用它的 agent 在目标任务分布上具有高 in-task performance。工具、执行 harness 和终止协议固定；产物是小模型权重。

- 学习收益指完整 agent 任务的收益，不是教师文本相似度或局部 checker 通过率。
- 方法必须跨任务使用同一数学程序。允许各 benchmark 的官方执行器、工具 schema 和回报适配，不允许按 benchmark、错误类型、调用/弃答标签选择不同算法或写阈值规则。
- 首先完整实现一个规模受控的端到端版本，再通过组件变体研究性能。数学正确性和泄漏检查必须先通过；新组件暂时没有优势不等于基础设施停止交付，但不要无依据扩大昂贵实验。
- 保留现有 RTD v1.1 作为可复现参照。新分支暂称 unified replacement，不擅自宣布新版本成为主方法或已经达到 ICLR 创新门槛。
- 读取当前仓库的 AGENTS.md、PROJECT_STATE.md、实验日志、最新方法文档与配置；依据实际文件确定状态。历史聊天中的路径、作业号和成绩只作线索。
- 在现有授权的数据、算力和费用范围内自主完成可逆实施与验证。优先复用已购池，不需要新增 teacher 调用就不要调用。需要超出现有明确授权的支出时，先交付可审查的配置、成本估计与已有结果；不要重复请求已经获得的授权。
- 不触碰无关项目，尤其不要把 scaling-down law 项目的计划混进 RTD。若仓库有未提交修改，保留它们，必要时建立独立工作树。

最终交付代码、测试、配置、完整方法说明、实验计划、实际结果、耗时剖析和下一步判断。所有实验结果必须能追溯到数据、配置、初始化和代码版本。

## 1. 必须保留的历史认识

1. 当前动作替换的价值不等于把证据蒸馏后对整个学生的学习价值。任务回报必须用于评价更新效果。
2. 稀疏字典、PCA 和全局 capability atom 没有证明增量价值，不重新依赖它们。局部梯度 sketch 可以作为计算近似，但不能重新包装成已验证的能力原子。
3. 少量自采样动作被当成硬答案反复强化，可能造成分布漂移。软来源估计、采样刷新、剂量与噪声必须明确。
4. 原来的 d 只调整学生 G1−G2，固定教师剂量的一阶比较中教师项会消掉。新设计要让教师剂量与来源选择真正联合决定。
5. 等 token 采购比较容易被成本、训练步数、曝光次数混淆。只胜出 retained-event efficiency 不等于 teacher-token efficiency。
6. RTD 骨干没有额外的直接 RL optimizer step；回报决定蒸馏控制。也不能因此否认方法使用了回报引导的策略改进思想。
7. α、d 与 a1、a2 是重参数化关系，这本身不是新颖性。真正研究的变化是联合控制、梯度估计器，以及它们是否产生更好的学习效果。

## 2. 核心设计：一个来源到教师的替换决策

### 2.1 对象与固定量

一次提交开始时，固定：

- 当前小模型参数 θ；
- 本预算轮的冻结来源策略 p_t；
- 已购教师文本 y_i^T；
- 当前教学状态 s_i，包含任务、工具上下文和完整交互历史；
- 曝光权重 w_i、统一的损失归一化规则；
- 优化器预条件器 P 和用于几何惩罚的正半定度量 H；
- 本步的来源采样、反馈和实际提交的版本标识。

在每个状态从 p_t 新采 m 条行为 Y_ij。第一版 m=2，使用项目已冻结的随机采样协议。不能为了使两条行为不同而拒绝采样或改 prompt，也不能按格式、正确性过滤这些来源。

G_ij 是当前 θ 对行为 Y_ij 的 NLL 梯度；G_i^T 是当前 θ 对教师文本的 NLL 梯度。教师只需提供文本，不提供 logits 或参数梯度。

### 2.2 统一决策变量

对每条学生来源设置 a_ij∈[0,1]，表示该来源份额中有多少交给这份教师示范。

本次采样的经验目标为：

qhat_i = (1/m) Σ_j [(1−a_ij) δ_{Y_ij} + a_ij δ_{y_i^T}]。

其中 δ_y 表示集中在行为 y 上的单位质量。目标天然非负、归一化；重复的行为必须合并理解其概率质量。

m=2 时：
α_i=(a_i1+a_i2)/2；
d_i=(a_i1−a_i2)/2。

α、d 只作为解释性统计量，不再分别由 state-only gate 与另一求解器产生。不要将 a1、a2 的重新命名写成贡献。

固定 α 指固定教师来源的系数，不代表教师行为的总目标质量固定。若 Y_i2=y_i^T，学生来源也会给同一个行为贡献质量。

### 2.3 新估计器：不能直接复用旧 α 加权软替换

记 Gavg_i=(1/m)Σ_jG_ij。经验目标的原始冻结权重梯度为：

graw_i = Gavg_i + (1/m)Σ_j a_ij(G_i^T−G_ij)。

建议实现的主估计器为：

gCV_i = Gsoft_i + (1/m)Σ_j a_ij(G_i^T−G_ij)。

Gsoft_i 是与来源采样测度一致的软保留梯度。两式逐样本相差 Gsoft_i−Gavg_i，差中没有自适应 a 的乘子。

这不是旧式
(1−α_i)Gsoft_i + α_iG_i^T − (d_i/2)(G_i1−G_i2)
的简单换名。m=2 时，新旧估计器相差 α_i(Gsoft_i−Gavg_i)。

理论规范：

- 若 E[Gsoft_i]=E[Gavg_i]，则即便 a 由本次来源样本及反馈共同选择，主估计器与原始经验目标梯度的无条件期望相同。
- 平均范围是来源采样以及反馈/选择过程。给定已实现的样本对与控制结果，gCV 不等于该经验目标的精确梯度。
- qhat 的非负性属于原始经验目标；单个有限批次的 gCV 不一定对应某个非负监督目标。实现可以显式组合冻结系数的梯度或带符号损失，但不能把它误写成每批次都在拟合 qhat。
- 求导时冻结整个本步目标生成规则、采样分布与控制输出。不得宣称这是包含目标随 θ 改变的端到端总导数。
- 旧的带自适应权重的软替换差 (1−α)(Gsoft−Gavg) 不自动具有零期望。不要沿用旧 α 在采样前固定的证明。
- Gsoft 的前缀分布必须与 hard source 相容；不同 teacher 前缀上的 KL 不能冒充它。
- 若现有 hard loss 按每条随机生成文本的实际长度归一化，先推导这个口径下的匹配 soft 估计器。不要直接套用总序列 NLL 的恒等式。第一版理论可采用总 token NLL 或采样前确定的缩放，但修改训练口径必须显式记录并匹配对照。
- 更新前冻结 P，确保理论中的参数增量与代码一致。梯度无偏不代表重新运行有状态 Adam 后的更新无偏。
- a 全零时精确回到 soft 保留；只有当前模型等于来源快照时，这个保留梯度才精确为零。
- a 全一时 gCV=G_T+Gsoft−Gavg，仅在期望上等于纯教师梯度。必须测量这个端点的方差，不声称逐批次等同于 CE。
- 无偏性不消除反馈选择过拟合。独立确认集继续必需。

主分支使用上述无权重控制变量估计器。保留 raw estimator 作归因对照。若主估计器的端点噪声确实损害性能，可以研究在当前采样前固定的控制变量系数或独立采样估计器；必须先写清对应目标、无偏性和方差，不能临时按任务/错误类别切换 loss。

### 2.4 教师条件的更新方向

固定当前样本与 P，定义：

b_ij = −(η w_i/m) P(G_i^T−G_ij)。

当前参数上的正式更新满足：

θ+(a) = θ − ηPΣ_i w_iGsoft_i + Σ_ij a_ij b_ij。

基本单位是“具体教师示范替换具体学生来源”的更新。使用全部方向的完整交叉项，不只保留学生差异方向之间的 Gram。

自然退化必须正确：

- G_i1=G_i2≠G_i^T：两列相同，来源分配可能不唯一，但总教师剂量仍可调整。
- G_ij=G_i^T：该列为零，不强求非零系数。
- 学生梯度为零、教师梯度非零：仍存在教师学习方向。
- 重复或线性相关方向不需要人为命名、聚类或强行正交化。

## 3. 一个联合控制目标

### 3.1 共同参考与精确求解

先实现数学最清楚的 exact/local-oracle 版本，供后续近似器学习和比较。这里 exact 仅指对已构造的局部代理问题求解到数值精度，不代表知道真实最优任务收益。

本步选择 a_ref 作为参考替换方案，在本次同一批证据、来源采样、曝光和初态上构造 θ_ref=θ+(a_ref)。第一版可使用所有状态一致的固定参考量；沿用当前初始化强度前先核查配置。它是通用初始化超参数，不是根据 benchmark 或错误类型制定的规则。

在 θ_ref 上收集完整训练反馈任务，估计 h=∇J(θ_ref)。J 是训练协议下随机 agent 从任务起点执行的期望完整任务回报。

沿用并核查现有回报梯度估计器。可实现的第一版是轨迹 score-function 估计：对每条反馈轨迹，用完整任务回报减去合法 baseline，乘该轨迹学生生成动作的 log-prob 梯度，再按任务采样权重平均；工具返回和环境文本不进入动作梯度。baseline 必须不依赖当前动作，或采用有依据的独立/留一估计。采样温度、实际采样分布和求导的 log-prob 必须一致；训练随机策略回报与官方近 greedy 分数分别报告。若使用离策略反馈，需明确校正与误差，不直接套用同策略无偏结论。可只计算 U^T h 所需的投影，避免存储不必要的完整 h。

令 x=a−a_ref，U 的列为 b_ij；求解：

maximize F(x)=hhat^T Ux − (λ/2)x^T U^T H Ux − Σ_l ε_l|x_l|
subject to −a_ref ≤ x ≤ 1−a_ref。

可用辅助变量把绝对值项写成标准凸 QP。λ、度量、反馈估计和求解精度必须在配置中定义。若使用其他信任域版本，作为明确变体。

- θ_ref 和正式提交都从同一原始 θ 与优化器状态产生，不在 trial 权重上继续多走一步。
- 正式更新与构造 U 的样本、曝光、P 必须一致，检查实际 Δθ 与预测 Δθ。
- x=0 是可行参考。回报没有信息时应由同一目标保持参考教学，不让所有控制因冷启动直接停学。不得凭空制造正回报。
- 反馈用于估计控制方向；学生骨干只提交定义中的蒸馏更新。
- 不穿过解出来的 a 去修改本次学生梯度。快速控制器另行训练，不恢复一个独立 α 元目标。
- 联合 K 的交叉项可能引起协调。不能使用“每个 |z_i|≤ε_i 就令 a_i不动”的逐项硬规则，这在有交叉项时并不一般成立。
- K 是几何惩罚，不是真实 Hessian 或任务损伤矩阵。Gram 应为正半定，记录数值误差与任何修复。
- ε 若来自经验标准误，仅能称不确定性正则；要声称经优化选择后的保守置信界，必须建立同时有效的误差控制并写明假设。

### 3.2 可声称和不可声称的理论

请补全以下证明与反例，而不是只贴一个通用 Taylor 不等式：

1. 经验目标合法性、重复行为合并以及来源对交换后的更新不变性。
2. 自适应选择下无权重控制变量的无条件期望恒等式。
3. 线性优化器近似中，实际更新与联合问题的仿射对应。
4. 明确一类条件：来源选择能产生标量教师加权无法达到的学习—保留效果；明确受限比较类，不能声称所有其他算法不可能做到。
5. 若 h 的同时误差界有效、λ覆盖局部平滑常数、实际更新吻合，则保守代理正增益怎样推出相对参考的局部收益下界。
6. 近似梯度、有限反馈、采样方差、近似求解误差如何进入界。

“联合问题包含分块问题，所以最优值更好”“目标归一化”“方向含教师”只是基础性质，不足以独立支撑 novelty。不得宣称全局最优、每步成功率单调、所有任务上都有效。

## 4. 采购：预测新增证据如何改善同一个教学问题

### 4.1 定义完整学习价值

令 D 为已购证据。TeachingProblem 定义共同参考、可执行更新集合和完整局部收益 F_D。采购价值使用：

A(Q)=E[F*(D∪Evidence(Q))−F*(D) | 购买前信息]。

这里必须包含教师带来的基础更新收益，不能沿用仅评价 d 相对均匀蒸馏收益的标签。否则两个学生来源相同但教师可以教会新行为的证据仍会被估为无价值。

比较 D 与 D∪Q 时：

- 使用相同当前学生、反馈梯度、参考点、总更新计划和旧证据权重。
- 不因添加新证据就重新平均全部旧权重。
- 新证据必须可分配零实际增量。仅令 a=0、却强制新增状态 KL，不等于可忽略新证据。
- 推荐先冻结候选状态/曝光槽及其免费学生保留基线；购买只开放该状态的教师替换方向。其他满足同一嵌套性契约的实现也可，但需明确推导。
- 若同一学生来源槽有多个已购教师 continuation，改用各教师版本的系数 a_ijv≥0，并约束 Σ_v a_ijv≤1；保留来源质量为 1−Σ_v a_ijv。不能把每个教师版本都视为独立的完整 box，重复替换超过该槽的总质量。也可预先分配独立且总曝光权重固定的槽，但必须全程采用同一约定。
- 候选集合改变参考时，必须保留相对共同参考的位移项，不能把新增教师的基础收益在重新中心化中消掉。
- 多查询预算优化不简化为永久标量收益/token排序。考虑已有证据冗余，输出批量联合或逐次重新定价的可行方案。
- 价值仍是局部代理，不是实际成功率，也不自动包含未来信息增益；非正一步价值不是全局停止证书。

### 4.2 预测器

第一版用冻结学生表示和小型预测网络/集成或核模型。不要为了“更新颖”直接训练大型 Transformer，也不要重新引入未验证的全局 capability atoms。

输入仅限购买前可见信息：

- 任务状态、工具/历史表示；
- 免费获得的学生行为/不确定性；
- 请求 continuation 上限；
- 当前学生/优化器版本、训练进度；
- 当前教学问题摘要、剩余预算与已有证据摘要。

输出同一求解器需要的低维统计分布：

- 候选教师替换方向与任务回报方向的对齐；
- 与已有替换方向的关系；
- 方向范数/尺度；
- token 成本及不确定性。

不得使用未购买教师文本、教师梯度、验证结果或真实未来输出长度。不要独立预测每个 Gram 元素后默认 PSD；可用共享预测向量因子构造一致的 Gram，记录表示近似误差。

购买后保存购前特征，再计算真实 teacher–student 方向、成本和共同参考下的完整 F 增量，形成训练标签。旧证据可在新 θ 上重算而不新增教师费用，但其计算成本要记录。过时标签必须带版本，不当成当前精确响应。

保留按父任务分组的预测验证，以及随机获取的数据或可记录的选择概率，避免只在被自己挑中的样本上评估预测器。

为降低候选重求解成本，可先用当前局部目标对新增方向的边际导数/对偶价格筛查，再对少量候选重求解。简化二次目标下它涉及 t^T(hhat−λHΔ*)；有其他约束时要加对应项。该筛查是同一目标的近似，不是另写一个经验价值函数。

## 5. 加速：近似同一控制问题，先找真正瓶颈

### 5.1 先剖析

分别计时并记录峰值显存：

1. 学生采样；
2. teacher/replay；
3. source/teacher/soft 梯度；
4. sketch、metric、Gram 构造；
5. 反馈任务 rollout；
6. QP；
7. 控制预测器；
8. 正式骨干提交；
9. 保存、恢复及其他调度。

20 状态×2来源约40个控制变量，不能先假设 QP 是瓶颈。若主要耗时在反馈与高维梯度，优化求解器几毫秒没有实际价值。没有测量前不承诺加速倍数。

### 5.2 摊销控制器

exact 版本能工作后，再训练一个小型控制器近似联合解。控制器输入当前可见的状态/来源/已购教师表示、批次摘要、训练上下文和反馈摘要，输出 a_ij∈[0,1]。这不是第二个 LLM student，也不是原来的 state-only α gate。

第一版使用冻结表示、共享轻量头与对来源排列一致的集合汇聚；若源顺序交换，输出和更新应相应等变。只把确有必要且通过留出验证的输入加入，避免复杂网络过拟合少量 support。

训练记录来自高质量教学问题与求解结果。训练损失优先比较：

- 同一个 F 下的 decision regret；
- 实际更新向量/预测收益；
- 可行性。

不要只回归 a 的逐坐标 MSE：方向重复时系数解不唯一，MSE 会错误处罚等效解。求解器标签自身也是局部代理，不能当成最优真实回报标签。

比较三种执行方式：

- exact；
- amortized-only；
- amortized 初始化加少量有界迭代修正。

修正可使用投影梯度等标准方法，迭代数与容差预先冻结。使用真实问题修正和使用预测问题修正是不同近似，分别标注。

训练反馈和几何在固定校正窗口刷新，普通步使用预测/缓存摘要；记录反馈年龄与漂移。减少测量改变了信息质量，不得伪装成完全等价的纯实现优化。

必须把产生控制器训练标签、训练预测器和校正窗口的成本计入总时间，报告摊销何时回本。若仍完整执行全部反馈与高维矩阵计算，不能宣称实现了主要加速。

## 6. 先实现可替换接口

沿用现有包和命名风格；以下为语义接口，不要求逐字新建文件：

- build_prequery_features(query, context)
- purchase_or_reveal(query, ledger)
- build_teaching_problem(context, owned_evidence, frozen_exposure)
- solve_exact(problem)
- predict_control(observables)
- commit_distillation(problem, coefficients)
- collect_task_feedback(checkpoint, feedback_split)
- build_acquisition_labels(old_problem, revealed_evidence)
- score_query_batch(prequery_features, context)
- validate_and_report(run)

TeachingProblem 必须版本化且不可变，包含 θ/p_t/P/H、损失定义、样本/教师文本 hash、曝光权重、参考系数、反馈版本、U/K/不确定性表示和可行域。trial、正式提交、采购反事实与控制器损失复用同一个核心目标实现，禁止各处复制略有不同的公式。

不要按梯度符号、类别或错误类型路由 CE/DPO；约束与连续控制由统一目标产生。保留标准 SFT/pairwise 作为实验基线，不把它们混成主算法的手工规则。

## 7. 执行阶段与预期结果

### P0：代码与数学契约

先完成实际实现、数据和预算审计。CPU/小模型玩具测试包括：

- qhat 非负、归一化、重复行为合并；
- 来源交换等变性；
- 相同/零/教师相同梯度退化；
- 当前模型等于快照时 soft 保留零梯度；
- a=0 与 a=1 的实际值、期望、方差分别检查；
- 枚举有限动作与任意样本依赖选择器，核对 raw、新 CV 的期望，并构造旧 weighted-soft 在自适应 α 下失效的反例；
- 前缀与随机长度归一化一致性；
- K 的 PSD、box 可行性、目标数值最优性；
- trial/commit 真实参数增量一致；
- 学生 optimizer/RNG/初态恢复、无多余骨干 RL 更新；
- 采购“新证据零使用”等价性、隐藏字段不可见、预算支出一致。
- 同一状态购买两个教师版本后，目标仍非负、归一化；新增版本系数置零，精确恢复原目标和实际参数增量。

预期：数学对象、实际 loss/gradient、更新映射三者一致。失败先修到可解释，不用 benchmark 调参掩盖。玩具测试通过不代表机制性能有效。

### P1：固定教师池验证蒸馏

2026-09-11 D15 数值审计补记：ALFWorld Luna 的生产 V0 在首轮 source
scoring 的 43-token action 上触发 mean guard：mean |delta|=0.05232027349、
max |delta|=0.54536819458 nats/token，无结构错误、无超过 1.0 的 outlier。
该失败批为两个相同的 629-token prompt，没有 padding。39 次检查共 2,136
tokens 的加权 mean=0.02507123649，最大单 token delta=0.70945930481。
D3 smoke 通过不能保证生产 V0 的全部来源动作通过同一阈值。

本地代码及 CPU tiny Gemma 4 检查核对了采样 logits、FP32 概率、位置、
mask、原生 softcap 和 KV 路径；未发现温度、错位或 multimodal padding
不一致。证据支持 bf16 12B 的 batch shape / decode-vs-prefill 舍入漂移，
不把它表述成已完成 A100 复现。全部三个 ALFWorld `*_luna.yaml` 的
`score_consistency_tolerance.mean_abs` 统一设为 0.08；库默认及非 Luna
配置仍为 0.05，max_abs=1.0、最多两个 outlier、hard max=8.0 和 D15
短动作规则保持不变。比较臂必须采用同一声明；P1 的其余冻结条件不变。

显式非默认阈值保存在 manifest 的 `score_consistency_tolerance_override`；
`score_consistency_observed` 持续记录 token-weighted mean、最大 action mean、
最大 token delta、检查/失败/token 数及 journal hash。失败检查先持久化再抛错，
恢复从 journal 重建；重复计算作为已发生的尝试计入。只有观测摘要排除于
不可变身份 hash，阈值仍受恢复验证约束，改阈值需新 run。论文应报告阈值、
三种 delta 统计及覆盖范围，不将放宽容差当成性能改善。详见
[D16 的 D15 follow-up](rtd_v1_1_d16.md#d15-follow-up-alfworld-luna-bf16-score-consistency-2026-09-11)。

先 BFCL 与 ALFWorld。采用同一初始化、同一合法已购池、同一曝光计划、同一机器和 matched 优化/调参预算。机制探索先遵循项目当前单种子协议；最终复现按用户最新冻结的种子设置执行并分开报告训练方差和评测重复方差。

最低核心比较：

- D0：充分调好的教师 SFT＋软 KL；已有调好 pairwise 锚点一并报告。
- D1：原分块 RTD，保留原 α gate＋d 程序。
- D2：新估计器下的 state-scalar 限制 a_i1=a_i2，联合调整各状态标量，测试是否仅仅是教学重加权。
- D3：统一来源替换，完整交互，精确局部求解。

先完成匹配小预算闭环，再开展以下有针对性的归因：

- D3 vs 去交叉项/分组交互：联合几何是否有用；
- D3 vs raw estimator：新估计器是改善稳定性还是引入额外方差；
- D3 vs 打乱来源对应：控制是否利用了行为与方向的正确对应；
- D3 vs 固定平均替换量的限制版本：把剂量变化和选择性贡献分开；
- D3 vs 同反馈/计算预算的通用元重加权或受约束回报修正。

最后一个强对照需要先写清方程；若与 D3 代数等价，应报告等价性而不是重复跑一个不同名字的臂。不能只用不给反馈的弱 baseline 证明控制机制。可增加“蒸馏前回报参考”对照检验教师参考更新的作用，但不能把它夸大成覆盖所有 RL 基线。

预期现象：

- 同池下 D3 改善目标任务收益—保留损伤曲线，且不只依赖更大的平均教师系数。
- 相同学生梯度时，仍可通过教师差异学习；没有有效区别时，不人为制造“选择性成功”。
- 交互有实际作用时 full 版本优于独立控制；若无增量，如实简化。
- raw/CV 差异与梯度噪声、格式漂移、剂量有一致解释；不要预设 CV 必然优于 CE。

判读：

- 只胜出整体 RTD，不胜出 scalar 限制：证据支持重加权，尚不支持来源选择。
- 只比高剂量不稳定 baseline 好：证据支持稳定性。
- 与通用回报修正相同：不得宣称特殊知识传输。
- 置信区间宽或有效任务组少：标 INCONCLUSIVE；不要当成已经证伪或确认所有机制。
- 若发现具体失败机制，可在统一目标内研究少数明确变体，例如估计器、步长/信任域、反馈频率；先登记假设和代价，不漫无目的扫参。

### P2：完整预算流程与采购

统一蒸馏器固定后，比：

- 随机购买；
- 正确记账的便宜优先；
- 原 Bayesian scalar-value 采购；
- 新教学响应预测＋同目标价值；
- 购买后真实响应的 oracle，仅诊断上界，不作可部署主结果。

先离线封存回放跑通，再在已授权 API 预算内做 prospective 版本。两种预算口径不能混合。AppWorld 在核心确认后补充长程执行验证，避免三基准同步复制全部探索矩阵。

报告教师实际支出下的任务表现曲线、到达相同表现的教师成本、预测误差/选择 regret、重复证据边际价值、代理与真实学习收益关系，以及总训练曝光。

若oracle有效而购前预测无效，问题在 acquisition estimator；若oracle也无优势，先检查价值目标、候选池与蒸馏器，不通过加深网络解决。

### P3：速度与可部署性

固定教学问题与任务协议，比较 exact / amortized-only / amortized+修正。

报告：
- 相同骨干训练量下的任务表现和总耗时；
- 相同总 GPU/环境预算下的任务表现；
- 反馈 rollout 数量；
- 局部目标 regret、实际更新偏差；
- 控制器训练与校正成本；
- 加速是否跨学生训练阶段保持。

预期：快速版保留 exact 的主要收益，且总成本下降。若仅 QP 变快、总时间不变，不算主要加速结论。若省掉反馈造成性能下降，报告 Pareto 权衡，不隐瞒。

## 8. Benchmark 与预算审计

以最新仓库协议为准，以下为必须核查的已知风险：

- BFCL 官方 Overall；全量生成完整性检查。temperature 0.001 与严格 greedy 的 0 分开描述，不混用。不同硬件的 base 不混作训练种子。
- AppWorld 主指标用官方完整任务 TGC。pooled unit-test pass ratio 只作诊断。dev40/max24 与历史 dev57 不直接拼表。检查早期事件与状态阶段覆盖，但不写成按阶段选择 loss 的规则。
- ALFWorld valid_seen 用开发；反复使用过的 valid_unseen 不重新称 untouched test。新模型是否改善初始低能力和已有能力学生可作互补机制检验。
- support 的教学与反馈按父任务/轨迹/模板分组隔离；最终校准与确认集不能参与采购、特征归一化、控制器训练或选择 checkpoint。
- 多个 benchmark 检验同一算法程序，不要求共享参数方向或同一组语义原子。

生成独立 budget manifest，至少包含：
benchmark、teacher_id、student_init_hash、pool/split版本、cost_regime、整数token cap、实际支出、exact/estimated组成、估算方式、失败/重试、生成池成本、历史采集成本、剩余预算。

BFCL 历史的 55,370 内容成本、13,843 cap、16,748 某池采集成本，以及更早百万级演示输出来自不同口径/池，不能混合。ALFWorld 可用包输出和全部尝试成本同样区分。

- sealed replay 只声称模拟访问协议下的预算效率。
- prospective 成本包含全部产生收费输出的教师尝试、失败、重试、生成与验证调用。
- 0 新 API 调用不等于 0 教师成本。
- warm-start 若已消耗教师证据，记录累计与增量成本，不把已适配模型称作未训练 base。
- 预算配置用明确整数上限；百分比仅作基于审计 manifest 的派生标签。
- 保证实际扣账不超过 cap；未购买输出的实际长度不能提前用于排序。学生 rollout、环境和 GPU 单列。
