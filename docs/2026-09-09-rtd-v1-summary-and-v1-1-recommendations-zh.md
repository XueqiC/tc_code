# RTD v1.0 汇总与 v1.1 详细建议 — 2026-09-09

写作依据:各 run 目录的 manifest / trajectory / teacher.jsonl / compute.jsonl / report,官方 BFCL v4 评测 csv,docs/rtd_v1_1_budget_quota_plan_zh.md(codex 起草的修订方案)。本文是我的判断,不是执行授权;未改任何代码。

## 1. v1.0 sealed_replay(BFCL)结果汇总

| R0 | hpg B200 | 45.53 | (跑中) | — | 2 / 188 | r2 |

分轴(仅诊断):所有终点 NL 79–80、Live 77–78、MT 49–50、Mem 23–29、Irrel 82–83、Web 8–12.5;没有任何轴出现超出噪声的系统性移动。

结论:**所有终点都在 base ±1.3 内,臂间差异 <1.8**,与 R0 随机采购不可区分。hpg R1 r3 的 +0.57 不构成信号。

### 1.2 机器效应
同一购买轨迹(R0 第 1 轮,2 包)在 rai Ada 得 46.81、在 hpg B200 得 45.53,差 −1.28,恰好等于噪声带。结论:**跨机器数字不可比**;matched 比较只能是 hpg 三个 B200 作业之间,或 rai 同一卡类之间。rai 上 R0/R1/R1s 分别在 Ada / A100 / RTX PRO 三种卡上,严格说不是同硬件比较。

### 1.3 采购机制的诊断(来自 trajectory.json 的 selection 记录)

| 指标 | R0(随机) | R1 / R1s(学习价值) |
|---|---|---|
| 每窗候选数 | 310(奇数轮,折 0)/ 111(偶数轮,折 1) | 同 |
| empty 的选择概率 | ≈ .50(先验 replay_prior_mass=.5) | .44–.56 |
| 非 empty 部分的熵 / 均匀熵 | .62–.65 | .56–.69 |
| 每轮实际购买 | 2–3 包 | 2–3 包 |
| 冷启动期望成本(cost model) | 8k → 0.8k | 8.5k → 0.6k |
| 实际单包成本 | 53–188 tok | 64–293 tok |

三点含义:
1. **学习价值几乎没有重塑采购分布**:R1/R1s 的候选分布熵比与 R0 的均匀分布相同量级,empty 保持一半概率。步骤 1/4/7/10 上 empty/购买交替出现,本质是抛硬币。
2. **成本从未约束**:窗口预算 20 万–410 万 token,单包 ~130 token;cost model 冷启动按公开 cap(65,536 / 8,192)预测成本,对所有候选几乎一样,价值-成本对偶无从区分。
3. **每轮候选池按折切换**(310 ↔ 111),偶数轮只能在 111 包里选,采购泛化空间被折进一步压缩。

### 1.4 其它诊断
- 反馈 rollout(温度 1 采样)的**格式错误动作逐轮增加**:hpg R1 0 / 12 / 36,rai R1s 0 / 10 / 50(按失败计分)。greedy 官方分未受影响。机制(2026-09-09 用户核对后修正):RTD 没有 RL 步更新骨干,回报梯度只进门控 VJP 与插入价值;上升来自传输目标的自身质量项 (1−a)·(−log p_t) 对温度 1 自采样(未按格式过滤)的似然最大化。v1.1 必须逐轮上报此指标并处理自采样格式。
- 教师 bank 内容:420 包共 55,370 recorded token(均 132/包);公开 cap 之和 8.26M;预算上限 825k / 2.06M / 4.13M。上限是内容的 15–75 倍。
- 一步更新的线性化误差检查(规范 §7.3)未做;固定 ledger 2×2、强对照(§10.3)未跑——在 v1.0 的采购量下都没有信息量。

### 1.5 判断
v1.0 的空结果是**结构性**的:每窗至多 1 包、12 窗、单包 ~130 token,总采购 ≈ bank 内容的 3%,预算永不绑定;在此之上学习价值再准确也无法在 4B 学生的 Overall 上产生 >1.3 的变化。它**不是**门控、插入价值或回报反馈失效的证据,也**不能**用来支持它们有效。

## 2. 对 v1.1 的详细建议

codex 方案(docs/rtd_v1_1_budget_quota_plan_zh.md)在预算、配额、曝光三处的定义我基本同意,下面按"采纳 / 修改 / 追加 / 不做"列出,并给出一个**先于六臂重跑的低成本判定实验**。

### 2.1 采纳(codex 方案原样)
1. **预算分母 = bank 实际 recorded 内容 55,370 tok**,10/25/50% = 5,537 / 13,843 / 27,685;硬账本不变量 S+H ≤ C 保持。
2. **每类内容认证 cap**:demo_attempt 2,048、generator_item 512(可用 bank 每类最大 recorded cost 向上取 2 的幂)。这需要一个明确的信息例外:允许特权离线 ingestion 对冻结 bank 发布"总成本 + 每类一个上界",selector 仍看不到逐包成本。不批准此例外则 10% 点永远买不到东西,方案应如实作废。
3. **每窗口配额**:累计预算不重置、窗口余额结转;Q_window = min(R, max(⌈R/W⌉, c_max));每窗最多 K=20 个新付费请求;M=40 次子决策机会,empty 消耗一次机会不返还;R0 用同一 M/K/Q 与成本对偶的随机抽取。
4. **曝光**:slots_per_step 8 → 40,每新包 2 槽,买不满的位置回给旧数据(不把少数包放大到 .25);多包共用同一参考回报梯度的一阶插入价值;VJP 按 (1−αm) 与 α 的线性组合。
5. 不变项:门控、一步实际更新、REINFORCE+LOO、评测、身份、单种子、ε=.25、正混合。

### 2.2 修改
1. **主比较改为 hpg B200 三臂**(R0/R1/R1s 同时提交,同软件/驱动),rai 只作 exploratory 副本(三种卡类),或 rai 上一类卡串行三臂。v1.0 里 rai 三臂在三种卡上并行的做法不再作为 matched 比较报告。
2. **预算主点 = 10% 与 25%**;50% 只作上限(K=20 下第 3 轮多半仍不绑定)。报告按实际支出画曲线,并逐窗记录 constraint binding / stop reason。
3. **cost model 冷启动**:保留"预测=公开 cap"的规则,但 cap 已降到 2,048/512,冷启动期望成本从 8k 降到 ~1k 量级,对偶才有意义。

### 2.3 追加(我的建议)
1. **先做"价值信号可靠性"判定实验,再决定 rollout 预算**(约 2–4 GPU·h,B200 一张卡):在同一参考点 θ_D⁺(取 hpg R1 第 1 轮第 1 步的 checkpoint 与状态),对全部候选包计算插入价值 v_q 两次,每次用**独立种子**的反馈 rollout(当前 8 父任务 × 4 rollout);报告两次 v_q 的 Spearman 相关与 top-20 重叠。再用加倍 rollout(16×4)重复一次。
   - 若相关 ≈ 0:在当前 rollout 预算下 v_q 只有噪声,K=20 重跑等于"换了包装的随机采购",应先提高反馈 rollout(或改用 2 折内更多父任务)再重跑;
   - 若相关明显 >0 且随 rollout 加倍上升:进入六臂重跑,并把该相关作为每窗必报的诊断。
   这个实验只读已有 checkpoint,不改协议,不需要教师 API;它直接回答"v1.0 的空结果是剂量问题还是价值本身没有信号"。
2. **每窗必报诊断**(写进 report):候选分布熵比、empty 概率、top-1 概率、v_q 离散度 / 噪声方差比、实际 vs 预期成本、格式错误 rollout 数。这些在 v1.0 里都已被记录但没有汇总,导致空结果的原因要事后挖 trajectory 才看到。
3. **候选池按折切换的处理**:保留两折(泄漏规则不变),但在 report 中按折分别给出可买/已买/未买数量,并把"偶数轮候选只有 111 包"写进结论限定;不建议为此改折规则(会改变支持父任务的身份链)。
4. **固定 ledger 2×2 与强对照放到 v1.1 结果之后**,在 v1.1 的最终 ledger 上做(C27 已实现 prepare/tune/run,可直接用);v1.0 的 ledger 不值得再花评测算力。
5. **自采样格式(方法项)**:传输目标的自身质量项只保留可解析的自采样,或让门控把格式错误来源的 a 推到 1;每轮上报温度 1 解析失败率。(原稿写成"观察/回滚"护栏,按用户核对改为方法项。)

### 2.4 不做
- 不改门控特征、不加类别/错误类型特征、不做 3 步 Adam unroll、不改评测(官方 v4 全量);不用隐藏逐包成本给 selector 排序;不加轮次或延长窗口来"凑满"预算;不把 rai 异卡结果与 hpg 合并比较。

### 2.5 算力与时间(按 codex 方案估算 + 实测)
- 训练梯度槽从 96/轮升到 ≤640/轮,估 v1.0 的 2–3 倍:B200 每臂三轮 + 三次评测 21–33 h;rai 32–50 h。
- hpg 三臂并行 + 接力作业:约 1.5–2 天出全部终点;rai 副本按可用卡类另计。
- 判定实验(2.3.1)额外 2–4 GPU·h,建议先做。

### 2.6 需要你拍板的项
1. 信息例外:允许每类内容认证 cap(2,048 / 512)。
2. 分母 55,370 与 10/25/50% 三点;主点 10%/25%。
3. K=20 / M=40 / S=40 / 每包 2 槽的组合。
4. 先做 2.3.1 的价值信号判定实验(约半天),再决定是否直接六臂重跑或先加 rollout。
5. 主比较 = hpg B200 三臂;rai 只作副本。
