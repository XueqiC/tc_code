## 6. 先导:片段收益的 split-half 可重复性

设计(预注册):16 个训练用反馈父任务 × 4 次 T=1 rollout,A=(1,2)、B=(3,4);每半内配对估计
ĥ_j = ½(R_j1−R_j2)[∇log p(τ_j1)−∇log p(τ_j2)],不共享 baseline;u_i 用真实 AdamW 单步导数;中心化;β=0.01;
G_{A→B} = Σ_i (w_i^A − p_i) u_i^B;bootstrap 按父任务(2000 次)。原作业 1024586 在 5 h 上限处超时(B 14/16),
改为从保存的 64 条 rollout 重打分(作业 1025190,`results/cr_diagnostics/segment_pilot_v1_rescore/segment_pilot.json`)。

| 指标 | 观测 | bootstrap 95% |
|---|---|---|
| 有对比的父任务(A / B) | 1 / 1(其余 15 个两次均失败) | — |
| 中心化收益 split-half 相关 | 0.154 | 2000 次里 1157 次无定义 |
| 两半收益差 RMS / 最大 | 79.6 / 826.9 | [0, 225] / [0, 2317] |
| G_{A→B} / G_{B→A} | 182.0 / 95.0 | [0, 546] / [0, 285] |
| 权重集中度 | w_max = 1.0,有效片段数 1.0 | — |
| 权重与长度 / 梯度范数相关 | −0.04 / 0.09 | — |

结论(预注册措辞):在当前模型、反馈任务与 M=64 下,尚未识别出可靠的再分配收益;原因是学生在 T=1 采样下 31/32 对
无对比(两次都失败),估计器被饿死,而非片段间无差异。旧 RTD 固定 RMS 候选映射的权重与片段长度相关 1.00,只反映长度。
修法:反馈任务取学生成功率居中的题、每题更多样本、或部分回报(F1);均不需新教师调用。

## 8. 分析与讨论(初稿,机制部分待补)

### 8.1 "合理的 support size 与 budget"——答案不是一个数,而是三个事实

1. **预算买到的不是监督,而是尝试。** 原 react6 池 535k 计费 token 中,57% 的题最终验证成功,但验证轨迹的 403 步里 59% 是
   格式失败(裸答案)——可蒸馏回合只有 154 个(4.6k token)。换 react7 后,149k token 买到 136 条验证轨迹、461 个合法回合
   (20k token):**同样的题,监督量 ×3,花费 ×0.28**。"budget"应当以可蒸馏回合计,而不是 token 计。
2. **support 200→400 不带来增益。** S=400 的两格(+0.4 / +0.6)与 S=200 同档持平。在 B ≤ 500k 且每题 ≤3 次尝试的规则下,
   support 只有在 S < B/2,680 时才绑住预算;更大的 support 只是换了买哪些题。
3. **剂量是唯一明显有效的旋钮。** 3 遍曝光(3–113 步)下所有 16 个格都在 ±1.3 内;10 遍(1e-5)下 react6 的 (200,300k) 到 +3.6 ± 1.3,
   (200,500k) +1.4、(128,300k) +1.2;3e-5 无一致优势。这说明此前 Table 1 与 stage 1/2 用的"24 步 / 3 遍"配方本身就不足以
   让任何方法显出差别——与 doseB 更新器空操作的发现是同一类问题的两面。

### 8.2 对论文设置的建议

- 正式设置:**support-200(已声明访问)+ react7 教师 + 全量购买(≈150k output token)**,配方 AdamW 1e-5、≥10 遍整回合曝光,
  报告"验证轨迹 / 合法回合 / 监督 token / 优化步数"四个量而不只报 token。
- 预算轴的正确画法:x 轴用可蒸馏回合数(或验证轨迹数),token 作第二坐标;3 遍与 10 遍两条曲线并列,说明剂量效应。
- 普通 SFT 在这个学生 + 任务上的 headroom 约 +1 ~ +3 pp(dev-500 ±1.1–1.3 SE)。若机制的增益要可见,需要两个种子以上,
  或换到 headroom 更大的基准(ALFWorld 已知 SFT 有效)。

### 8.3 本轮的偏差与教训(如实)

- Codex 的合成测试两次放过了真实接口:`stop` 参数(44 次尝试在发请求前失败,账面 90k、真实 0)与 provider 失败计费(24× 账面)。
  规则:采购工具先用 1 并发探测、看第一条真实结算行,再放量。
- 三轮账本校验放宽(Azure 零计费拒绝行、版本化 model 串、未结算保留、react7 身份按不变量)都是"校验器比数据严格"的问题,
  没有改动任何数据。
- 先导作业在 5 小时上限处超时(梯度 B 14/16);已改为从保存的 64 条 rollout 重打分,不再重新采样。
- 节点 3 报过 (200,500k)×10 的部分值 +3.7,完整值 +1.4,已更正。
