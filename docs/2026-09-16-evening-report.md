### 1.4 材料的性质(收紧后的表述)

ALFWorld 的 luna 银行**没有可见的推理监督**:采集提示是 "Reply with exactly one admissible command and nothing else",
`behaviors[i].text` 就是裸命令。不输出 Thought 不等于教师没有推理,因此不能把退化归因于"不再思考"。
对照 HotpotQA 的 react7 银行监督的是完整回合(`Thought n: … / Action n: …`),同一套纯 CE 在那边是正增益。

解析器事实(`src/alfworld_eval.py::pick_command`):只取回复**第一行**,做完全/大小写/双向子串匹配,失败回退 `look`。
`ACTION: <命令>` 可被接受;`THOUGHT: …` 开头的多行回复会被判成 `look`。教师侧另有取最后一个 `ACTION:` 的解析,学生侧没有。
**若要重采完整 ReAct 示范,必须同时修改学生侧解析器。**

## 2. HotpotQA 支持集扩充(补购)

### 2.1 口径

预算 = **教师被查询的 support 任务数**(每题最多 3 次尝试,取第一条通过验证的轨迹),按原始训练集百分比锚定;实际花费作为结果报告,不作为旋钮。

### 2.2 本轮采购

| 项目 | 数值 |
|---|---:|
| 冻结顺序中新查询的父任务 | 1,609 |
| 验证成功 | 1,067(66%) |
| 教师真实失败 | 481 |
| **我方基础设施失败(Wikipedia 限流)** | **61** |
| 计费输出 token | 1,174,631 / 1,210,000(97%) |
| 加上原 support-200 的 149,169,HotpotQA 教师累计 | 1,323,800 |

支持集按"冻结顺序 + 跳过基础设施失败的题"来数:**1%(904 题 = 200 + 704)完整可用**,其中验证 614(68%,与原 support-200 的 136/200 一致);
2%(1,809 题)只凑得出 1,548 题,差 61 题(补齐约需 45k token,超已批上限约 4%)。

材料已合并为 `envs/hotpotqa/teacher_pool_scan/r7_s904`(904 题 / 1,606 次尝试 / 614 验证 / 665,173 计费 token)与银行 `data/rtd/v1_1_hotpotqa_luna_s904`,
与 ALFWorld 使用同一个预算化 runner,便于两个基准逐项对齐。

### 2.3 限速与代价(工程)

采购初始只有 3.3 次尝试/分,瓶颈是令牌桶按每请求预留 2,048 token(桶 50k/分 → 24 请求/分),而实际每请求仅用 50–150 token;加 `BFAS_TEACHER_TPM` 覆盖后解开。
随后撞上 Wikipedia 限流:32 并发 39% 尝试失败、10 并发 32%、**4 并发 0%**。61 个永久损失的父任务由此产生,单列为本方基础设施失败。

## 4. 工程事故与纪律(如实记录)

- **采购限速**:令牌桶按每请求预留 2,048 token、桶 50k/分 → 24 请求/分封顶,而实际每请求只用 50–150 token;加 `BFAS_TEACHER_TPM` 覆盖后解开。
- **Wikipedia 限流**:32 并发时 39% 的尝试失败、10 并发 32%、4 并发 0%。我的高并发试探使一批父任务三次尝试全部耗尽在限流上,**这是本方的基础设施损失,不是教师能力失败**,单列记账。
- **pkill 自匹配**:再次用 `pkill -f <含自身模式>` 杀进程,连带杀掉自己的工具 shell 与监视器(exit 144)。已改为先查 pid 再逐个 kill。
- **跨主机审计**:FSCD 主干工具按字节比较 base_model 清单(含宿主路径元数据),rai 上生成的审计在 LONI 永远对不上;作业改为在训练主机本地重建行并断言计数一致。
- **部署纪律**:LONI 上正在训练的格子,其评测阶段会重算 source_hashes;**训练期间不得覆盖部署树的源码**,否则几小时的训练会在评测阶段失败。
