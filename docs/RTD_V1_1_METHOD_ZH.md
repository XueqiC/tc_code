# RTD v1.1:完整方法(Return-guided Repair-Transport Distillation)— 2026-09-09

本文是 v1.1 的完整方法说明(独立成文,不依赖 v1.0 文档),供审阅与作为实现规范。所有"轮"指预算轮,不是种子;全程单训练种子(seed 0)。v1.0 → v1.1 的差异见附录 A。

## 1. 问题设定

- 目标:在**教师 token 预算** B 下,把一个黑盒教师(只返回文本)的能力蒸馏进一个小 agent 学生 π_θ(4B),终点是学生在官方 benchmark 上的完整任务表现(BFCL v4 Overall;ALFWorld valid_seen 成功率;AppWorld TGC)。
- 学生可访问自己的完整分布(logits);教师只能通过"在某个状态 s 上请求一段续写"来访问,每次请求有 token 成本。
- 三个耦合的决策:**买什么**(在哪些状态上请求教师、请求多长)、**怎么用**(把教师证据以多大强度、以什么目标传输给学生)、**何时停**(预算与曝光)。
- 单种子探索阶段的比较对象:同硬件、同软件、同任务清单、同评测参数的对照臂;报告方向与数值,不构造跨机器噪声带。

## 2. 对象与资源

### 2.1 状态、动作、来源分布
- 状态 s:任务提示 + 已执行历史(BFCL 单轮为完整提示;多轮/ALFWorld 为执行到某步的完整历史与观察)。动作 y:学生一次完整输出(含终止)。
- 来源分布 p_t:本轮开始时冻结的学生快照在 s 上的动作分布。每状态采样 2 个来源前缀 Y∼p_t 用于估计(§4)。
- 教师证据 ν_D(·|s):教师在 s 上的文本续写(整段,含终止),来自 bank(封存回放)或在线请求。

### 2.2 教师 bank、请求包与硬账本
- 请求包 q = (状态、请求长度上限 L、公开成本上界 cap、类别)。封存回放模式下,包的真实响应与真实成本被封存,selector 只能看到公开视图;购买("揭封")时按记录成本扣账。
- 硬账本不变量:已结算 S + 未结算预留 H ≤ 授权 C;reserve → reveal → release 语义;失败/未购不扣账;同一包只付一次。
- 预算口径(v1.1):分母 = bank 的 **recorded 内容成本**(BFCL C25 bank:55,370 token),**明确标为"缓存内容成本实验"**,不称为完整在线教师账单。预算检查点 10% / 25%(两个预算轮末),27,685(50%)只作上限。
- 每类公开 cap(v1.1):按冻结 bank 内容认证——demo_attempt 2,048、generator_item 512——这是一个**新的公开成本假设**(允许特权离线 ingestion 对冻结 bank 发布"总成本 + 每类一个上界",selector 仍看不到逐包成本)。
- 基座学生:**发行方原始 checkpoint** Qwen/Qwen3.5-4B(官方 BFCL 46.06),**未进行本项目的 bank 适配**(项目日志只能保证这一点,不能证明发行方预训练未见过某个公开题目);泄漏审计:manifest 记录基座训练数据哈希,bank 构建时与候选基座训练行做 prompt/响应/任务重叠检查;CRCD 系列 checkpoint 禁用作基座。

### 2.3 曝光与决策窗口
- 每个预算轮 12 个提交步(每步一次学生实际更新),其中 4 个**决策窗口**(步 1/4/7/10)可购买新包。
- 每个决策窗口固定 **曝光槽 E=40**:最多 K=20 个新包,每包占 1 槽,其余由旧证据(已购包 + 参考池)按原来源→状态→教师分布填充。买 0 包 = 该窗口只训练旧证据。
- 支持父任务 m 与两折:父任务按哈希分两折,奇/偶轮交替作为"内层(训练来源)"与"反馈"折;反馈折只提供回报,不进入训练梯度、预条件器或归一化。校准集与 support 留出永不进入训练/采购。**BFCL:m=40 个支持父任务**(40 个官方题 + 5 个生成种子函数按父哈希分折;候选包 420 = 84 示范尝试 + 336 生成项,按所属父任务归入当轮内层折才可买)。**ALFWorld:135 个训练父组全部是支持集**(折 0:79 组,折 1:56 组),每轮内层折 = 候选池(其 107 个可用包中折 0:63、折 1:44)+ 来源状态,另一折 = 反馈池;4 个探测父组永久排除。few-shot 设定以此为准。

## 3. 模块 I:来源保持的证据传输目标

### 3.1 目标
对每个训练状态 s,以来源分布 p_t 为起点,把质量向教师证据转移:
q(y′|s) = Σ_y p_t(y|s) K(y′|s,y),K(y′|s,y) = (1−a(s,y)) δ_y(y′) + a(s,y) ν_D(y′|s),
学生目标为 q 的正混合交叉熵:
L(θ;s) = E_{Y∼p_t}[ (1−a(s,Y)) ℓ_src(θ;s,Y) + a(s,Y) ℓ_T(θ;s) ],
其中 ℓ_T = −log π_θ(教师续写|s)(完整动作,含终止),a∈[0,1] 为门控(§5),没有教师证据时 a=0(identity)。

### 3.2 来源项的估计器(v1.1 的核心改动)
期望意义上 E_{y∼p_t}[−log π_θ(y|s)] = H(p_t) + KL(p_t‖π_θ),在 π_θ=p_t 处梯度为零:来源保持项本身不会放大错误;风险在于用 2 个硬样本近似整分布并反复拟合(样本偏差被放大)。v1.1 用学生自己的完整分布消除不必要的采样噪声:

- **软来源目标**(固定门控与标量门控):
  ℓ_src^soft(θ;s,Y) = Σ_j KL( p_t(·|s,Y_<j) ‖ π_θ(·|s,Y_<j) ),
  仍采样来源前缀 Y,但每个前缀位置用完整词表分布(冻结快照 vs 当前学生)。性质:π_θ=p_t 时**每个已采样前缀上的梯度恒为零**,不依赖大量样本相互抵消,也不需要识别哪个输出格式错误。这不是额外的 KL 正则,而是同一来源保持项的更准确实现。
- **控制变量估计**(来源依赖门控 a(s,Y),门控与采样结果相关,不能直接换目标):
  ĝ_CV = (1−a) G_hard + a G_T − c_s (G_hard − G_soft),
  G_hard = 来源硬样本 NLL 梯度,G_soft = 同一前缀上的软交叉熵梯度,二者期望相等;c_s 与当前样本独立。
- **冻结的实现约定(三臂同一估计器)**:所有臂(V0/V1/V2)统一使用 CV 更新器;每状态 2 条独立来源样本 Y_1,Y_2,样本 i 的系数取 **c_i = 1 − a(s, Y_{3−i})**(用另一条样本上的门控,避免与当前样本相关);固定门控 a=.5 时它自然退化为软来源梯度,来源依赖门控时保持控制变量形式。**每个提交步都从本轮冻结来源模型重新采样**,不复用缓存的硬样本;门控 VJP 穿过实际更新,**包括 c_i 对门控的依赖**;采样分布、软分布与终止/截断处理在三臂中完全一致。
- 三条限定写进协议:(i) 方差是否下降必须实测(§8 的嵌入对照);(ii) 元梯度必须经过**新的**更新算子(不复用旧 VJP);(iii) 一般形式只作刷新样本的梯度估计器,不把可能出现的负系数固定成多轮 signed-CE。
- 语法/格式过滤**不进入主方法**(它改变来源分布并需定义被删质量去向),只作诊断对照(最后做)。默认实现现在就定为 soft/CV,不根据 §8.2 小实验中哪个官方分最高临时更换主方法。

### 3.3 批量窗口的统一损失
决策窗口购得集合 S(|S|≤K)后,本窗口实际更新的损失为
L_S = (1 − |S|/E) L_D + (1/E) Σ_{q∈S} L_q,
L_D 为旧证据(参考池)上的 §3.1 目标,L_q 为新包 q 的状态上的 §3.1 目标;系数非负、和为 1;S=∅ 退化为 L_D。购买数量由预测收益、预算与可用曝光共同决定,不再对每窗指定 50% 的 empty 概率。
- **固定实现**:决策步按上式批量混合更新,更新后新包并入当轮旧池;非决策步按冻结的抽样规则从累计池训练。

## 4. 模块 II:一步实际更新与真实回报

- 参数空间 = LoRA 可训练参数;预条件 P = 训练侧来源梯度的 RMS 对角;步长 η 由训练折 KL-pilot(目标 KL≈0.005/步)确定;θ⁺ = θ − η P g,其中 g 为 §3 目标的 CV 估计梯度(写进 manifest)。
- **两个取值点分开**:决策窗口先做**虚拟参考更新** θ_D⁺(只用旧证据),在 θ_D⁺ 上取回报梯度 g_J(θ_D⁺) 供插入价值(§6.1);随后按 §3.3 的批量混合做**实际提交** θ_S⁺,在 θ_S⁺ 上取回报梯度 g_J(θ_S⁺) 供门控元梯度(§5)。参考计算与额外 rollout 单独记账;不为省一次 rollout 把实际学生的梯度塞进参考点公式。
- 回报 J(θ):反馈折上完整任务的随机 rollout(温度 1)得到的官方成功指标(BFCL checker 0/1;ALFWorld 成功;AppWorld TGC);每个反馈父任务 K 次 rollout,REINFORCE + 同任务 leave-one-out 基线;所有采样动作都经"生成 vs teacher-forced 似然一致性"记录(均值硬阈值、逐 token 离群计数)。
- **回报梯度只用于两处**:门控的元梯度(§5)与插入价值(§6)。**学生参数不做任何 RL 更新**(v1.0 已核实;v1.1 保持)。

## 5. 模块 III:用真实回报元学习门控

- 门控 a(s,Y) = σ(φ·χ(s,Y)),χ 为购买前可得的来源/状态特征(来源似然、长度、投影等;不含类别或错误类型特征)。标量门控变体:a=σ(φ₀)。
- 元梯度:∂J(θ_S⁺)/∂φ 经**实际提交更新** θ_S⁺ 的 VJP,通过 §3.2 的 CV 估计器求(含 c_i 对门控的依赖);每个决策窗口一次 gate VJP,φ 以小步更新。
- 固定门控 a=.5 作为 V0 的对照。

## 6. 模块 IV:预算约束的批量采购与持续价值学习

### 6.1 插入价值
对候选包 q,在共享的参考回报梯度 g_J(θ_D⁺)下,一阶插入价值 v_q = −η ⟨g_J, P (g_q − g_D)⟩,按位置份额 1/E 计入;空集合的价值为 0(继续训练旧证据)。记录每窗联合更新的实际收益与局部可加预测 Σ v_q/E 的误差(不假定可加成立)。

### 6.2 采购决策
局部目标:max_S Σ_{q∈S} ṽ_q / E,s.t. Σ_{q∈S} ĉ_q ≤ B_t,|S| ≤ K;ṽ_q 为价值后验的一次采样(Thompson),ĉ_q 为成本后验的预测;B_t 为本窗口可用授权(累计预算不重置、余额结转)。贪心/小规模精确求解,记录约束是否绑定与停止原因。V0 用同一预算、同一 K、同一成本模型的随机抽取。
- **与硬账本的执行顺序(V0/V2 共用执行器)**:求解候选集合 → 按固定顺序逐包 reserve(按公开 cap) → reveal 并按记录成本结算 → release 差额 → 更新剩余授权与候选 → **用实际购得的集合构造 §3.3 损失**(预测约束 Σĉ_q ≤ B_t 不等于实际都能预留;训练器只用实际购得集合,并记录计划集合与实购集合的差异)。10%/25% 是授权上限,横轴用实际支出,不强求花满。"失败不扣账"只限于未产生消费的本地预检失败;在线请求一旦产生收费输出,即使任务失败也计费。

### 6.3 持续价值与成本后验
- 价值后验(贝叶斯线性,购买前特征 → 插入价值)与成本后验**跨轮保留**;每个标签保存反馈估计的不确定性(同一批 rollout 对多个已购包同时估插入价值及协方差);
- 每轮用已购参照包重测学生变化导致的价值漂移,漂移 → 增大后验不确定性,不清空历史;
- 价值可靠性检查:只在已购包或明确扣账的校准包上,用两组独立反馈估计的相关衡量;不对未购候选计算真实 v_q(不打开封存池);
- 成功标准不是"采购分布熵下降":价值不可靠时接近随机是合理行为;要检验的是可靠的价值差异出现后决策是否随之改变。

## 7. 模块 V:开发评测与认证
- **开发评测**(本阶段实现):每个预算轮末导出实际学生(LoRA 合并)并做官方评测(BFCL v4 全量;ALFWorld valid_seen 140 题 greedy;AppWorld 官方执行),评测 harness 身份冻结(评分文件投影 + 数据 + 模型/分词器 + 设备类),审计过的身份更新可复用已完成评测。
- **认证**(最终阶段):冻结模型后,在预留的独立数据上报告统计界(bootstrap 任务采样),才称为认证;开发评测的分数只用于本阶段的方向决策。
- 报告按**实际支出**画曲线(10%/25% 两点),同机差分直接给方向与数值;教师成本、加权曝光、实际计算分别报告。

## 8. 运行协议(v1.1)

### 8.1 三臂(hpg B200 同机;单种子;2 个预算轮)
| 臂 | 采购 | 蒸馏 | 回答 |
|---|---|---|---|
| V0 | 随机批量采购(同预算/同 K/同成本模型) | §3.2 改进估计器 + 固定门控 a=.5 | 基准 |
| V1 | 复用 V0 的购买记录(固定 ledger) | §3.2 改进估计器 + 学习门控(§5) | V1−V0:怎么蒸馏 |
| V2 | 持续价值后验 + 预算约束批量采购(§6) | 与 V1 相同 | V2−V1:买什么 |
V0 先跑(它的 ledger 是 V1 的输入);V2 与 V0 并行;V1 随后。每臂 2 轮 × 12 步,窗口 {1,4,7,10},每轮末官方评测。**V1 重放 V0 的购买时间、状态曝光、包权重与重复次数(不只是包 ID)**,来源输出由 V1 自己的冻结学生重新采样——这样 V1−V0 才能解释为"同样证据,更会蒸馏"。V2−V1 是**自适应采购的整体效果**(含采购改变后续学生与来源分布的作用),不称为严格隔离的数据主效应。

**结果决策表(两轮三臂完成后)**
| 结果 | 下一步 |
|---|---|
| V1 明确优于 V0 | 蒸馏侧形成主贡献,保留门控 |
| V2 在相近实际成本下进一步优于 V1 | 采购与蒸馏的统一框架获得支持 |
| V1 有收益,V2 无增量 | 固定蒸馏,集中改采购估计,不换框架 |
| V1 无增量 | 检查门控是否产生实质不同的更新,以及回报敏感度是否预测实际收益 |
| 三臂都改善但彼此接近 | 收益主要来自共同目标或数据曝光,暂不归因于自适应模块 |
三臂完成后再补一个**同已购池、复用现有强配置的 CE 或 pairwise 终点**(V0 是机制对照,不能独自承担"高性能蒸馏"的强基线)。

### 8.2 嵌入首轮的来源项对照(嵌入诊断,不决定主方法)
在已购数据 + 参考池上、同一 checkpoint、同门控/剂量/来源冻结周期下比较:原始 2 硬样本;soft/CV(默认);8 个独立硬样本;(诊断,最后做)语法过滤硬样本。观测:同状态重采的梯度范数方差;只做来源更新 12 步后固定任务集的解析失败率;完整任务表现。它回答"改善是否符合采样噪声解释",**不**用来在四者中挑主方法。约 4–6 GPU·h。

### 8.3 度量与健康指标(每轮必报)
- 固定任务集解析失败率(两折各固定 20 状态 × 温度 1 采样 K=4);梯度方差;每窗购买数/支出/剩余预算/约束绑定;联合-vs-可加误差;价值可靠性(已购包两组估计相关)与决策变化;官方 Overall(10%/25%)。
- 不用混合了折/轨迹长度/反馈次数的原始 malformed 计数。

### 8.4 不做
不加 benchmark 特定错误规则或类别特征;不做多步 Adam unroll;不缩减官方评测;不用跨机器差值构造噪声带;不把工具(控制变量、条件积分)本身当 novelty。

## 9. 理论能支持什么、不承诺什么
- 支持:(i) K 为概率核 ⇒ q 是合法分布,a=0 为 identity,教师缺失时目标不变;(ii) 软来源目标在 π_θ=p_t 处逐前缀梯度为零(精确);(iii) G_hard 与 G_soft 期望相等 ⇒ 控制变量估计无偏(c_s 与样本独立时);(iv) 插入价值是同一实际单步更新的方向导数,局部截断误差由 L-光滑界给出但 L 未知,只能实测;(v) 硬账本不变量与封存视图保证预算与信息边界。
- 不承诺:方差降低幅度;多包联合收益可加;价值后验在少量标签下可靠;跨 benchmark 的固定超参。

## 10. 三个 benchmark 的具体问题
- **BFCL**:bank = 420 包(84 精确成本示范尝试 + 336 估计成本生成项),内容 55,370 token;每窗候选 ~308(折 0)/~110(折 1);官方 checker 判定;解析失败率在固定状态集上测;主比较只在 hpg。
- **ALFWorld**:bank = 107 个真实环境重放验证过的历史示范 episode(estimated 成本),m=135 父组两折;回报 = 40 步内完整任务成功;评测 valid_seen 140 题 greedy;强 CE 锚点(77.86%)必须并列报告;实测 B200 一场 episode 生成 ~320 s,每轮约 10 h、每次评测约 10–12 h,用接力作业。
- **AppWorld**:冻结的同一程序;状态来自实际执行;官方执行与终局评测;若 cache 不支持在线失败状态,标记请求覆盖限制,不用最近邻教师回答替代。

## 附录 A:v1.0 → v1.1 的变化
