# 机理流程:从 50 条 query 到一个训好的学生(逐步走一遍)

用真实跑过的例子,把整条流水线从头到尾走一遍。

---

## 第 0 步:手里有什么

- 一个 benchmark(以 BFCL 为例),里面每道题 = 用户的一句请求 + 一组可用函数。
- **k=50 条 few-shot query**。这 50 条是"任务边界 T 的样本",固定不动。
- 一个 teacher(deepseek-v4-pro)和一个学生(Qwen3.5-4B)。
- benchmark 自带的判官:单轮题有官方 AST 检查器,多轮题有**可以真执行的后端**
  (文件系统、推特、记忆库都是真的,调用下去状态会变)。

---

## 第 1 步:先测学生 —— 这 50 道题它会几道?

让学生在每道题上试几次。每道题得到一个**通过率**(记作 p̂):

```
simple_python_31       4 次对 1 次   p̂ = 0.25
live_parallel_9-5-0    4 次对 1 次   p̂ = 0.25
web_search_4           4 次全对      p̂ = 1.00
multi_turn_base_58     4 次全错      p̂ = 0.00
```

测几次不是写死的:一道题**只在"再测一次可能改变对它的处置"时才继续测**
(后验还骑在决策边界上就接着测,已经能下判断就停)。

---

## 第 2 步:对每道题下判断(三选一)

把 50 道题按"可疑程度"排序(可疑 = 失败率高 **或** 还没测清楚)。
对当前最可疑的那道:

```
它确定比平均水平差吗?
├─ 是,且还能造出新数据 → 【花 teacher 的钱】给它生成变体(去第 3 步)
├─ 不确定(可能差可能不差)→ 【花免费的 rollout】再测,直到测清楚
└─ 确定不比平均差       → 放下,处理下一道
```

两个防呆:
- 对一道题生成到"**新数据不再改变对它的认识**"就停(它就是难,买再多也是重复)。
  之前没有这条时,一道题吃掉了 89% 的预算。
- "平均水平"按**题**算,不按测试次数算,否则被反复调查的难题会自己把平均拉高。

**副产品(重要)**:变体的表现能区分两种失败——
- `live_parallel_9-5-0`:原题错,但 6 条变体学生**全对** → 原题只是措辞怪,不用管。
- `live_parallel_multiple_10-9-0`:变体也**全错** → 真的能力缺口,重点投入。

---

## 第 3 步:生成数据(核心,举三个真实例子)

### 例 A:单轮题(1 回合的退化情形)

seed = `simple_python_31`(物理计算,学生 p̂=0.25)

```
1. teacher 看着原题和函数表,写出 4 道新题 + 每道的标准答案(该调用什么、参数是什么)
2. 验证:让【另一次独立的 teacher 调用】只看新题(看不到答案)去解
   → 用官方 AST 检查器比对两份答案
   → 一致 = 这道题"答案是确定的",收下
   → 不一致 = 把检查器的意见喂回去,让 teacher 改题,最多 3 次
3. 例:"小车以 15m/s 加速 2.5m/s² 走 8 秒,末速度多少?" + 对应调用 → 通过 ✓
```

### 例 B:多轮题(episode)

seed = `multi_turn_base_58`(推特+车辆控制后端,学生 p̂=0)

teacher 直接写出**整段对话剧本**,每回合三件套:用户说什么 / 该调用什么 / 调用完怎么回话:

```
回合1  用户:"我想把公路旅行计划发推特,先看我登录没"
       调用: posting_get_login_status(); post_tweet(content='...')
       回话:"发好了,带了 #RoadTrip 标签"
回合2  用户:"关注几个旅行账号,搜搜旧金山的推文"
       调用: follow_user('travel'); search_tweets('San Francisco')
       回话:"关注了,搜到你刚发的那条"
回合3  用户:"那个账号数据怎么样?顺便我关注了谁?"
       调用: get_user_stats('travel'); list_all_following()
       回话:"数据是...,你的关注列表是...【任务结束】"
```

**验证 = 把整个剧本在真后端上跑一遍**:回合2 搜到的必须真是回合1 发的那条推文,
回合3 的关注列表里必须真有回合2 关注的账号。跑不通 → 报错喂回去改,改不好丢弃。

### 例 C:边界的"反面"

- **整题拒绝**:teacher 写"这些函数做不到的请求"。
  例:函数只有整数 GCD → 生成"算 4.5 和 9 的最大公约数"。
  验证是镜像的:独立求解**也必须不调用**才收
  (如果独立求解居然调了,说明这题其实做得到,收下会教学生拒绝该做的事)。
- **中途静默轮**:剧本里约 1/6 的回合规定"这轮不调用"——答案上一轮已经有了,
  或者缺参数该反问。这是 benchmark 真实分布(12.4% 的回合不调用)。

### 为什么必须有 B 和 C:三次失败教出来的

| 数据里缺什么 | 训出来的学生什么样 | 补上后 |
|---|---|---|
| 没有"回话收尾" | **永远不停**(BFCL 多轮归零;AppWorld 步数打满) | 多轮 4→17 |
| 没有"拒绝" | **什么都调用**(Irrelevance 82→12) | 修回 75 |
| 没有"静默轮" | 每回合硬调用,把状态改坏 | 本轮验证中 |

每一条都不是设计时想到的,是**训完看分、按轴解剖、数数据构成**反推出来的。

---

## 第 4 步:组池 + 加权

所有通过验证的数据合成训练池(当前 955 行)。每行的训练权重:

```
权重 = (1 − p̂)  +  preserve × p̂
        ↑                ↑
   学生越不会,权重越大    学生已会的也留一点权重,
   (钱花在缺口上)         防止已有能力被覆盖(preserve 的值正在扫)
```

生成的数据全部来自学生做错的题,p̂=0,自动拿满权重。

---

## 第 5 步:训练

LoRA r16,3 epoch,4096 token 截断(尾截)。没有别的花样——**方法的重点在
数据侧,训练侧刻意保持最简**。

---

## 第 6 步:评测(两档,严格分开)

- **快评(20 分钟)**:固定的 306 题子集,只用来**排序和定方向**
  ("这版比上版好没好"),数字永不上报。
- **全量(3 小时)**:官方完整流程 5217 题,出可上报的数。

---

## 第 7 步:解剖 → 回到第 3 步

全量分出来后**不看总分,逐轴看**:哪条轴掉了 → 拉出该轴的逐题失败记录 →
统计失败类型和出错回合 → 对照"训练数据里有没有这类行为" → 缺就补(回第 3 步)。

这个循环今天转了三圈:补收尾 → 补拒绝 → 补静默轮。
下一个已知目标:多轮的**动作正确性**(错在前两回合就把状态改坏)——
方案是"学生自己走,在它走偏的那一步上,让 teacher 从那个状态给出正确下一步"
(在学生的错误现场买纠正,而不是只给它看完美示范)。

---

## 一句话版

**50 条 query 划出边界 → 测出学生缺哪 → 只为缺口造数据(正面:怎么做+怎么收;
反面:何时不做),每条数据都被 benchmark 自己的判官验证过 → 加权训练 →
按轴解剖找下一个缺口,循环。**
