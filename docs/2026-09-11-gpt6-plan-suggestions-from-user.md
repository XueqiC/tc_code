**可以。我建议把整篇文章收拢到一个根本问题：教师的一条成功轨迹，不等于当前学生最需要学习的内容。**

教师轨迹同时包含必要的决策、完成这些决策所需的推理，以及教师特有的表达和执行习惯。现有方法改善了轨迹质量和监督结构，但仍有一个值得深入研究的问题：

> **对于当前学生，究竟应该学习这条轨迹里的哪些内容，才能提高它独立完成任务的能力？**

这个问题可以同时支撑我们的蒸馏机制和预算分配，而且比“现有方法有全局 Damage，所以必须替换”更准确。

**首先，Fable 的两条论证不能直接进入论文。**

“全部替换必然造成全局损伤”不成立。如果两个任务使用独立参数，或者教师指导恰好改善了共享行为，完整模仿也可以没有损伤。选轨迹和调整权重同样会改变干扰，不能说现有方法只有 Gain 旋钮。

“few-shot 导致示范主要落在学生已经会的状态”也不是一般规律。我们自己的 ALFWorld 初始学生就是反例。

可以成立的表述是：**在有限容量和不充分覆盖下，降低教师模仿损失，并不足以保证完整任务成功率提高。** 我们的实验为这个问题提供了实例，而不是证明所有现有方法必然失败。

---

**我会这样组织论文的完整故事。**

我们面对的是一个具体任务族。用户提供少量示例、可用工具与任务级 verifier，希望用有限的黑盒教师调用，训练出一个小模型。部署时，把它放回相同的 agent harness，独立完成未见任务。

现有 agent distillation 通常先收集成功的教师交互轨迹，再训练学生复现其中的推理和动作。SmartAD 进一步选择学生更容易学习的轨迹，并强调动作和最终决策；SAD 区分不同功能片段；Kang 的方法利用工具交互轨迹和相应训练、解码设计。这些方法已经超出了普通的答案 SFT。[SmartAD](https://aclanthology.org/2026.findings-acl.1349.pdf)、[SAD](https://arxiv.org/html/2505.13820v5)、[Agent Distillation](https://arxiv.org/html/2505.17612v2)

但是，**成功轨迹告诉我们教师怎样解决问题，却没有直接告诉我们当前学生需要怎样被教。**

同一条教师轨迹中：

* 一些行为学生已经掌握；
* 一些行为与学生不同，但两种方式都有效；
* 一些动作确实需要纠正；
* 还有一些动作只有连同其前置推理和后续交互一起学习，学生才能掌握。

因此，问题不只是“这条轨迹好不好”，还包括“它的哪些部分对这个学生有教学价值”。

在 few-shot、预算有限的情况下，这个区别更重要。我们没有大量任务去平均掉监督偏差，也不能不断购买教师轨迹来弥补覆盖。**一笔预算不仅要买到正确示范，还需要买到当前学生能够有效吸收的指导。**

我们的历史实验正好支持这个动机：ALFWorld 中局部干预没有收益的示范仍能教会行为；BFCL 中正确的纠正可能伴随其他决策退化；AppWorld 中增加同类示范和曝光没有稳定改善。它们共同说明：

> **示范的执行价值，与示范经过训练后的学习价值，需要分开。**

为解决这个问题，我们提出一种**根据学习收益分配监督的 agent distillation 方法**：在学生真实访问的状态上获取教师指导，识别具有完整上下文的教学片段，学习哪些学生行为应被改变、哪些应被保留，再用同一个学习价值决定下一笔教师预算花在哪里。

这可以继续作为 RTD 的核心，但不必坚持原来的全部模块。

**你提出的 trace 内部 component，确实值得进一步研究，但关键不在于简单分配不同权重。**

Reason–act–observe 不是三个对称的预测目标：

| 部分                         | 在 agent 中的作用          | 蒸馏时应该考虑什么                        |
| -------------------------- | --------------------- | -------------------------------- |
| Reasoning                  | 为当前决策提供计算过程，也会进入后续上下文 | 哪些推理是学生作出正确决策所必需的？是否必须使用教师的表达方式？ |
| Action                     | 实际调用工具、修改环境或提交结果      | 该行为是否需要改变？学生是否已有有效替代行为？          |
| Observation                | 环境返回的信息，是下一步决策的条件     | 保留真实 observation；通常不作为学生生成目标     |
| Final response／termination | 决定如何交付结果、何时结束         | 必须放到完整任务表现中评价，不能仅检查工具调用是否正确      |

Observation 的 loss masking 已经是现有工作的标准处理；SmartAD 和 SAD 也已经区分 reasoning 与 action。因此，“action 权重大一点、reasoning 权重小一点”不足以成为新的核心。

**更值得研究的是组件之间的条件依赖。**

例如，教师的正确动作是在教师自己的推理之后生成的。我们把 reasoning loss 设成零，但仍把教师 reasoning 放在上下文中训练 action，学生学到的仍然是：

> 看到了教师这段推理之后，怎样生成正确动作。

这不等于：

> 学生使用自己的推理，也能生成正确动作。

这是一个具体、可测量的区别。它说明**只调整 loss mask，并没有自动解决学生推理与教师动作之间的条件错配。**

同样，改变了某个工具调用，就不能继续沿用原来的工具返回值。否则训练数据中会出现一条现实中不可能执行的轨迹。

所以，我建议将我们的教学单位定义为：

> **在真实上下文中成立、保留必要依赖关系的生成片段。**

它可以是一条动作，也可以是推理加动作，或者连续几个交互回合。单位大小应由教学效果决定，而不是为每个 benchmark 手写一套选择规则。

**按这个思路，方法可以落成五步。**

1. **让学生暴露自己的学习需求。**
   在 support tasks 和允许的训练环境内运行当前学生，保留完整状态、推理、动作、真实 observation 和终局结果。已有教师轨迹也可以提供学生尚未到达的教学状态，避免低能力学生永远看不到后续步骤。

2. **购买条件一致的教师指导。**
   把真实状态交给教师，请它提供一个动作或一段可执行 continuation。教师指导要适用于这个状态。若修改了动作，就重新执行环境并生成后续轨迹，不能拼接不匹配的 observation。

3. **区分教学内容与教学强度。**
   一方面决定学习哪个片段、是否需要连同前置推理学习；另一方面决定替换哪些学生行为、替换多少。组件类型可以作为模型输入，但不直接规定“reasoning 一律弱监督”或“action 一律强监督”。

4. **用学习后的完整任务表现训练这个决定。**
   判断依据是蒸馏更新对学生任务表现的净作用，而不是教师身份、文本相似度或当前分支是否成功。可以沿用 RTD 的共享反馈方向与周期性校准，避免为每个片段单独做一次完整试训。学生骨干仍通过蒸馏目标更新。

5. **用同一价值指导下一次购买。**
   如果缺的是动作选择，就优先购买相应指导；如果孤立动作教不会，而更完整的片段有更高学习价值，就购买更多上下文或后续步骤。这个选择来自历史学习反馈的预测，并接受真实收益校准。

这里有一个预算上的关键区别：**买完整轨迹后再把部分 loss 置零，只减少训练曝光，不减少教师支出。** 真正的采购收益必须来自查询内容或长度发生变化。

**如果希望在蒸馏目标上再推进一步，我认为最值得测试的是“保留学生自己的推理路径”。**

这比继续增加 component 权重更有潜力。

传统的联合模仿，要求学生提高“教师推理 + 教师动作”这一组合的概率。我们可以考虑：**只要学生的某条推理路径能够支持目标行为，就不必强迫它复现教师的那条推理。**

以单个决策回合为例，令 \(r\) 表示推理、\(a\) 表示动作。联合分布的 KL 可以分解为：

$$
D_{\mathrm{KL}}(P_T(r,a)\Vert P_S(r,a))
=
D_{\mathrm{KL}}(P_T(a)\Vert P_S(a))
+
\mathbb E_{a\sim P_T}
D_{\mathrm{KL}}(P_T(r\mid a)\Vert P_S(r\mid a)).
$$

这个标准分解说明：联合模仿同时匹配动作分布，以及给定动作时的教师推理实现。后者可能帮助学生计算，但并不是动作匹配本身必需的条件。

由此可以提出一个更明确的蒸馏目标候选：

$$
-\log \sum_r \pi_\theta(r,a^T\mid s).
$$

它鼓励学生通过自己的推理路径作出教师指导的动作，而不是固定模仿教师的整段推理。

**这与“只训练 action、但仍输入教师 reasoning”不同。** 前者考虑学生自己可能产生的推理；后者仍在教师上下文上学习。

我认为这值得作为一个独立 component variant，但目前不能把它说成已经解决的问题：

* 对所有推理路径求和不可直接实现，需要采样或变分近似。
* 学生推理可能影响后续上下文，因此当前动作相同不保证整个任务相同。
* 有些学生确实需要教师推理来启动学习，不能一律去掉。
* 仍需要核查其与已有潜变量学习、推理蒸馏工作的区别。

这条方向提供的是一个真正不同的**监督对象**，不只是又一个样本权重。

**“Code 是 agent language”可以用，但我建议把它作为执行结构，而不是论文的新颖性来源。**

CodeAct 已经提出用可执行 Python 统一动作空间，通过解释器组合工具并根据执行结果修正行为；SmartAD 和 Kang 的工作也已经使用了 CodeAct。[CodeAct](https://proceedings.mlr.press/v235/wang24h.html)

对我们而言，代码最有用的地方是提供可检查的结构：

* 哪个参数来自哪个 observation；
* 哪段计算为后续调用提供输入；
* 修改某个调用后，哪些后续步骤需要重新执行；
* 不同代码写法是否在当前测试中产生一致的结果。

这些信息可以帮助构造**依赖一致的教学片段**，也可以帮助识别值得保留的学生替代行为。

但不能把“stdout 一样”当作完整语义等价：代码可能有不同的状态修改和副作用。也不应为了使用代码而改变所有 benchmark 的 harness。BFCL 的函数调用、ALFWorld 的文本命令，同样可以按原生接口形成可执行决策。

而且，已有 SCoRe 已结合学生轨迹、教师纠正、CodeAct 和强化学习，因此“on-policy + 局部纠正 + 执行反馈”也需要作为近邻方法比较。[From Correction to Mastery](https://arxiv.org/html/2509.14257v1)

**我建议第一轮就围绕一个尖锐问题设计实验：教师轨迹里的哪些内容，必须被学生原样学习？**

固定同一批任务状态和教师指导，比较：

* 完整教师推理与动作蒸馏；
* 静态 reasoning/action 权重；
* RTD 的整回合选择性替换；
* 依赖一致的片段选择性替换；
* 学生推理路径上的动作蒸馏，作为上述边缘化方向的近似版本。

同时匹配教师支出、反馈使用、训练曝光，并单独控制总体教师剂量。看完整任务成功率，也看原来成功任务的损伤、有效替代行为是否保留。教师状态与学生状态的数据来源应另做一个轴，避免把 on-policy 的数据优势归给新目标。

我希望最终建立的论文主张是：

> **在少样本和教师预算限制下，高效 agent distillation 的关键，是识别当前学生需要改变的条件化决策，并提供足够但不过量的教学内容。我们据此构造选择性蒸馏目标，并以学习后的任务收益统一监督分配与教师采购。**

这条主线能容纳已有 RTD 的有效部分，也给组件级改进和学生推理路径留下明确的实验空间；其核心始终是**怎样把教师指导转化为更强的小模型 agent**。
