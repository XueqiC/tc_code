## 1. 这套机制要验证什么

**核心问题**:学生拿到已有的证据之后,如何作出下一步有用的决策。

两个可分离的子问题:
1. **材料怎么组织才能被学会**(I/P/L 三臂):把同一组操作目标,
   (I) 拆开单独教、(P) 放回真实交互上下文里教、(L) 按固定协议切连续片段教。
2. **材料能不能被自动找到**(读取器 G0/G1/G2):从学生状态检索相关的教学证据,
   并检验"任务 ↔ 执行反馈"的绑定关系是否被用上。

**这两件事被刻意解耦**:I/P/L 不等读取器胜出。

## 3. 路线 2:读取器(已完成,负结果,原因已查清)

### 3.1 第一版(哈希 unigram 读取器):null,但**仪器本身无分辨力**
四条件 N / O(正确 support 一次) / R(正确 support 递归) / M(绑定被扰动)。
结果:**O = R = M,87 个状态上选择完全相同,逐项配对差 0.000**。

按评审要求做了**五层结构核查**(零 GPU,用现有 87 状态):

| 层次 | 结论 |
|---|---|
| 输入 | M **确实**改了对应关系(循环错位),87/87 标记为已改变 |
| 表示 | 每条记录**先编成完整关系再聚合**,评审担心的"先加总再归一化"**不存在**;但扰动只造成 L2 中位数 **6.1e-4** 的变化 |
| 读取 | **真正原因**:注意力**几乎均匀**。62 条 support,均匀权重 0.0161,偏离均匀最大值中位数仅 **6.6e-4**;O 更是精确均匀 |
| 排名 | 分数**从不**完全相同(0/87),但排序 82–84/87 相同 |
| 预算 | **放大器**:可用 15 条只选 2 条,把残差量化掉 → 选择 87/87 相同 |

**所以那个 null 不能读作"递归注意力不成立"**,只能读作**当前测量在该量级上没有分辨力**。

### 3.2 第二版(有序键值记忆 + 预训练表示):仪器有分辨力了,结论仍是负的
改动:**每条记录先编成完整关系再聚合**;key = 任务与决策状态,value = 该状态的行动/结果/已有教学证据;
表示改用本地 Gemma-4-12B 的最后一层最后一个 token 隐状态(404 条请求,170 万 token,约 6 分钟,**不截断**)。

**正对照(新增的硬要求)**:植入已知大小的绑定差异,要求仪器必须测得出。
→ **可分辨的最小绑定差异 = 2e-6**(约 4e-6 RMS L2),比旧仪器测不出的 6.1e-4 **低两个数量级**。

**注意力尺度审计**(评审明确要求):

| 指标 | 中位数 | 最小 | 最大 |
|---|---:|---:|---:|
| 归一化熵 | 0.982 | **0.556** | 0.987 |
| 有效 support 占比 | 0.928 | **0.160** | 0.946 |
| **每案例**最大权重 / 均匀权重 | **1.463** | 1.195 | **13.54** |

**(此行已更正)** 我原先把 0.966 写成"最大权重/均匀权重"的中位数,那是**错的**:
评审指出在同一有效 support 集合、非负归一化权重下 max ≥ mean,该比值不可能小于 1。
核对后确认是我**标错了指标**:0.966 是**全部 5,394 个权重**各自除以均匀权重后的分布中位数
(其均值按构造恰为 1.0),不是"每案例最大权重"。真正的每案例 `max_weight_over_uniform`
是 **min 1.195 / 中位数 1.463 / 最大 13.539**,全部 ≥ 1,与评审的判断一致。
**实质含义也随之收窄**:中位案例里最受关注的那条 support 只拿到均匀权重的 **1.46 倍**,相当平坦;
13.5 倍只是尾部。

→ **多数案例仍接近均匀,少数案例出现真正集中。"预训练 embedding 不保证集中"。**
温度 0.1 事先冻结于合成开发材料,报告记录 `parameter_search_performed: false`、
`perturbation_optimization_performed: false`。

**结果**:

| 条件 | 遗漏率 | 预算内覆盖 | 失败位置覆盖 |
|---|---:|---:|---:|
| G0 当前状态直接读取 | 0.7384 | 0.2616 | 0.1429 |
| G1 保留配对,一次读取 | 0.7356 | 0.2644 | 0.1429 |
| G2 保留配对,递归读取 | 0.7318 | 0.2682 | **0.0** |

配对差:**G1 − G0 = 0.000**(86 对);G2 − G0 = −0.0039;失败位置覆盖 G2 − G0 = −0.1429(仅 7 对)。

**(口径已统一)** 评审指出均值表与配对差对不上(均值给出 −0.0028 / −0.0066,配对表给出 0 / −0.0039)。
已在**同一样本、同一权重**下重算:原因是**均值表各条件用了不同样本集**(G0 为 86 例,G1/G2 为 87 例)。
在三条件都可评分的 **86 个公共案例**上重算后**完全一致**:
G0 = 0.738372、G1 = 0.738372、G2 = 0.734496;**G1−G0 = +0.000000**(86 对中 6 对非零、相互抵消)、
**G2−G0 = −0.003876**(11 对非零)。均值之差与配对差**逐位相同**,不存在计算口径冲突。

**与上一版性质不同的关键证据**:

| 比较 | 排序相同 | 选择相同 |
|---|---:|---:|
| G1 vs G0 | 1 / 87 | 37 / 87 |
| G2 vs G0 | 2 / 87 | 15 / 87 |

旧仪器是 87/87 选择完全相同;现在 **G1 相对 G0 在 50/87 个案例上选了不同材料**。
**所以不能再用"仪器分辨不出来"解释这个 null。**

### 3.3 路线 2 的结论(收窄后)
1. **保留绑定确实改变了读取器选什么**(50/87 不同),
   **但按已标注证据的口径,选出来的并不更好**(G1−G0 精确为 0)。
2. **递归**改变得更多(72/87),覆盖只提高 0.4 个百分点,
   却把**对学生真实失败位置的覆盖从 0.143 打到 0**。两版仪器方向一致。
3. **限制照说**:失败位置那一列只有 **7 个可评分案例**;多数案例注意力仍近均匀,
   因此多数案例上的 null **仍部分**可归因于仪器。

**按评审意见收窄**:G1 与 G0 选择不同,只说明**新增输入改变了输出**,
**尚不能证明"正确绑定"被利用**——那需要**新版读取器自己的绑定扰动对照**(旧版的 M 不能替代)。
失败位置覆盖 0.1429 → 0 落在 **7 个案例**上,很可能只对应一个案例的变化,
**不宜描述成稳定损伤**。数值扰动可检测只证明**计算有灵敏度**,不代表表示理解了教学关系。
当前可写的结论是:**新版读取器确实改变了选择,尚无可靠的选择质量增益。**
读取器就此**冻结原型,停止继续调**,主要资源转给 I/P/L。

## 4. 教师教学链采集(已完成购买,素材当前不可用)

### 4.1 买到了什么
**24 条有效链 / 24 个不同父任务**(一父一链),停止原因是
**`target_chains_reached`(够了就停,不是钱花完)**。

```
145 次请求 · 14,058 / 30,000 output token · $0.084 / $5 · 拒绝 37 条
```

- **全部 24 条的 stop_reason 都是 `correct_executed_continuation`**:
  教师在真实上下文里提出后续动作 → **工具真的执行** → 取得有效后续。
- 链长:2 步 16 条 / 3 步 6 条 / 4 步 2 条。
- 验证只要求教师示范**正确且可执行**,**没有**用"能不能救活原学生"去筛
  (这正是早期"把即时干预价值当学习价值"的错误,已避免)。

### 4.2 预算机制(花钱前逐项实测过)
- 每次请求按**整个已发布上下文窗口 + 全部 cache write + 长上下文溢价**原子预留,单次 $0.526;
- 结算用真实用量取代预留(实测每次 $0.0014,全部 `usage_status: reported`);
- **并发实测**:8 进程同时抢且不结算,只批 9 次预留 = $4.73,**未越 $5**;
- provider 超出预留 → **停掉整轮购买**;用量解析不了 → **按全额计费,绝不算免费**。

### 4.3 当前的阻塞:0/24 可转成教学目标

| 拒绝原因 | 条数 |
|---|---:|
| 该链起点**不是分类器标出的候选纠正状态** | 21 |
| 教师目标里含 gold(构造器拒绝) | 9 |
| 执行路径未到达候选状态 | 7 |

**根因是我的编排错误**:给采集器的取材条件("学生已拿到工具观测且任务未完成")
比构造器要求的("分类器标出的那个失败状态")宽,两边对"该教哪个状态"的定义没绑在一起。

构造器另有一条**防挑拣硬规则**(候选状态必须全部有目标)。
**我当时判断"这条是对的",评审不认可,已按评审决定撤掉该要求**:
预算约束下部分教师查询产生不了有效示范,本来就是可能结果;
允许用已验证的示范建包,**代价是必须完整报告购买成功率、尝试范围、
哪些候选没拿到可用监督,且失败购买计入共同成本、评测不得因此删任务**。

## 6. 背景:Table 1 给机制线提供的立论(已完成并归档)

| 方法 | ALFWorld(base 56.4) | HotpotQA(base 38.2) |
|---|---|---|
| Agent Distillation | 58.81 ± 1.65(**+2.4**) | 37.20 ± 1.22(**−1.0**) |
| SAD | 58.81 ± 1.49(**+2.4**) | 37.60 ± 0.28(−0.6, n=2) |
| SmartAD | 58.10 ± 2.18(**+1.7**) | 37.80 ± 0.72(−0.4) |

**三个方法在 HotpotQA 上的三种子均值全部低于 base。** 留分寸:单个方法的下降都没超过自己的种子标准差。
但逐题比对显示:**三方法在 475/500 题上结果完全相同**(ALFWorld 上是 124/140),
**它们不是三个结果,而是一个共同行为**——在 ALFWorld 上有用,在 HotpotQA 上没用。

那 297 题三方法全错中:**176 题 gold 从未进过 observation**、145 题根本没结束。
**与路线 1 的诊断一致:瓶颈在检索侧的查询构造**,而这三种方法都是模仿教师轨迹,
并不直接教"如何根据已有证据构造下一次查询"。

**按评审意见收窄(原表述归因过强,已撤回)**:
- ❌ ~~"这三种方法并不直接教'根据已有证据构造下一次查询'"~~ —— 轨迹蒸馏**本来就能**在 observation 条件下监督下一次查询。
- ❌ ~~"475/500 成败相同 ⇒ 三者机制相同、失败原因相同"~~ —— 成败相同不等于轨迹或学习机制相同。
- ❌ ~~"gold 未出现 / 未结束 ⇒ 根因在查询构造"~~ —— 单凭这两项不足以定位根因。
- 另:SAD 目前仍是 n=2,**不能写成三个方法都完成了三种子**。

**当前最稳妥的动机表述**:
> 在当前预算与配置下,已有的轨迹蒸馏没有带来可靠的 HotpotQA 整体提升,
> 因此值得直接检验**局部教学的上下文组织**是否影响学习与迁移。
