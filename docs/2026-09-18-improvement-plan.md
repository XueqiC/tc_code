# 跨 benchmark 的提升方案(2026-09-18 草案)

> 依据全部来自本仓库已落地的测量,每条都标注了**证据强度**:
> **[已证]** 有配对检验或数值恒等支持;**[线索]** 方向一致但功效不足;**[提案]** 尚未检验,附预注册判据。
> 时间为 America/Chicago。

## 0. 先把"为什么现在提不动"讲清楚

四条已落地的测量,合起来解释了目前的困境:

| # | 测量 | 数值 | 强度 |
|---|---|---|---|
| 1 | **容量与监督量严重失配** | LoRA 65,568,768 参数;ALFWorld 监督约 6,745 token → **9,720 : 1**;HotpotQA 约 83,823 token → **782 : 1** | [已证] |
| 2 | **两个种子的解近似正交** | 154 步 ΔW 余弦 **+0.0215**;‖mean‖/平均‖·‖ = 0.7147(正交理论值 0.7071) | [已证] |
| 3 | **训练损失与基准表现反向** | 3/3 种子对中低损失者 EM 更低;154 步两种子逐步损失几乎重合(平均 \|差\| 0.067)却差 8.57 pp | [线索](双侧 p=0.25) |
| 4 | **监督信号偏向措辞** | HotpotQA 决策载荷仅占 **9.46%** 字符;CE 梯度 90.5% 落在不决定决策的 token 上 | [已证] |

**一句话**:我们在用**六千多个监督 token 去约束六千多万个参数**,目标函数既**约束不住方向**(→ 种子正交、剂量非单调),
又**指不对地方**(→ 九成梯度在措辞上)。在修掉这两点之前,换损失、换选择规则都是在噪声里挑花样。

## 1. 表现轴

### A1. 按监督量设定容量,而不是固定 rank 16 —— [提案,今晚在测]

**做法**:把 LoRA rank 当作**由监督预算导出的量**,而不是超参默认值。
经验规则(待标定):令 `参数量 / 监督 token 数` 落在 10²–10³ 量级,而不是现在的 10⁴。
对 ALFWorld 的 6,745 token,这意味着 rank 1–4 而不是 16。

**关键实现细节**:改 rank 时必须**同步改 alpha 保持 `alpha/r` 不变**(PEFT 的有效缩放是 `alpha/r`),
否则改的是有效步长而不是容量,结论会被混淆。今晚 r=4 的两格就设了 alpha=8。

**预注册判据**(作业 1033596/1033598,r=4 双种子,154 步):

| 结果 | 判读 |
|---|---|
| 种子极差 < 4.0 pp **且** 均值 ≥ base | **支持**:容量是种子敏感性的主因,降秩是有效且免费的稳定手段 |
| 种子极差 < 4.0 pp **但** 均值 < base | 部分支持:降秩稳住了方差却损失了表达力,需要在 r=4 与 16 之间标定 |
| 种子极差 ≥ 4.0 pp | **不支持**:容量不是主因,改找数据顺序/优化器噪声 |

(参照:r=16 时 154 步极差 **8.57 pp**、116 步 3.57 pp。)

### A2. 多种子权重平均(LoRA soup)—— [提案,今晚在测]

**做法**:同配置训 k 个种子,**精确**平均它们的 ΔW。
不能分别平均 A 和 B(数学上不等价);正确做法是把因子拼接:
`A_cat = vstack(A_i)`、`B_cat = hstack(B_i)`、`r' = k·r`、**alpha 保持不变**,
则 `alpha/r' · B_cat A_cat` 恰好等于各 ΔW 的算术平均。已对 328 对因子逐对数值验证恒等。

**代价**:零额外训练;只多一次评测。**任何 benchmark 都适用。**

**预注册判据**(作业 1033604,s0+s1):

| soup 的 EM | 判读 |
|---|---|
| > 70.71(两种子中较好者) | **强支持**:种子差异是围绕好解的噪声,平均可免费获得增益 |
| 62.14–70.71 | 中性:平均给出稳定的中间值,价值在**降方差**而非提分 |
| < 62.14 | **反对**:两个解是不同的真解而非噪声,平均会破坏它们(与余弦 0.02 的观察一致,这是**真实可能**的结果) |

⚠️ 诚实预期:余弦 +0.02 意味着两解近正交,**平均很可能落在两者之下**。
若如此,A2 应被**放弃**,并且这本身是一条有价值的负面结论。

### A3. 决策加权目标 —— [提案,需在扩大后的评测上跑]

**做法**:把损失集中到真正决定动作的 token(`search[...]`/`finish[...]` 括号内、ALFWorld 的命令本身)。
现状占比:纯 CE **9.46%**、SmartAD 13.68%、SAD 22.96%。

**但必须先说清楚**:ALFWorld 的决策占比本来就是 **100%**,它照样在 26–55 步崩塌、且种子极差 8.57 pp。
**所以"提高决策占比"不是万能药**,它只在决策占比低的 benchmark(HotpotQA 类)上有动机。

**前置条件**:HotpotQA 500 题的 MDE@80% 是 3.92 pp,**这个臂必须跑在 2,000 题上**,否则必然得到跨零区间。

### A4. 剂量必须按曲线选,且**不能用训练损失选** —— [已证 + 线索]

ALFWorld 完整曲线:20 步 55.00 → **39 步 20.71/22.86(崩塌,p≈1e-11~1e-13)** → 77 步 52.14 → 116 步 57.86/61.43 → 154 步 70.71/62.14。
**26–55 步是禁区**,且这与材料量无关(36 题 26 步同样崩)。
而训练损失在崩塌点已降到 0.53–0.61、在 154 步是 0.07–0.09,**全程单调下降,对崩塌毫无指示**。

**规程**:剂量选择必须依据**留出任务的 rollout 成绩**,不得依据训练损失或其收敛性。

## 3. 综合:一套可跨 benchmark 复用的配方

```
1. 量监督规模          统计银行里实际进入损失的 token 数 N_sup
2. 由 N_sup 定容量      选 rank 使 参数量/N_sup 落在 10^2–10^3;同步调 alpha 保持 alpha/r 不变
3. 量决策占比          统计决策载荷占 N_sup 的比例;低于约 30% 时才考虑决策加权(A3)
4. 定剂量              先用小步长扫 4–5 个剂量点,按留出 rollout 成绩选,**绝不看训练损失**
5. 跨过崩塌带          确认所选剂量在崩塌带之外(ALFWorld 是 26–55 步;其他 benchmark 需各自定位)
6. 多种子 + 平均        至少 2 个种子;若 A2 成立则平均,否则报均值与极差
7. 评测规模匹配效应量    先算 MDE@80% = 2.80·se,再决定评测集大小;效应量小于 MDE 就不要跑
```

**第 7 步是前置条件而不是收尾**:本项目此前大量实验之所以"不可判定",正是因为把它放在了最后。

## 4. 本方案不主张的事

- **不主张**"只监督决策"能普遍提分——ALFWorld 决策占比 100% 仍会崩塌(§A3)。
- **不主张** LoRA soup 一定有效——余弦 +0.02 下它很可能失败,今晚就会知道(§A2)。
- **不主张**降秩一定不掉分——可能换来方差下降与表现下降的权衡,判据已预注册(§A1)。
- **不主张**已发表的分段加权基线"无效"——它们在 HotpotQA 上**确实改变了模型**(86/500 题答案不同),
  只是净收益为零;在 ALFWorld 上则是**根本无从生效**。这两句话不能混为一谈。

## 5. A2(LoRA soup)的结果:**我的预测错了,而且是有用的方向**

作业 1033604,9 分 23 秒,EM **67.86**。

| 模型 | EM | 对照 |
|---|---:|---|
| base | 55.71 | — |
| seed 1 | 62.14 | 较差的种子 |
| **两种子算术平均(参考线)** | **66.42** | — |
| **LoRA soup(精确平均)** | **67.86** | **高于参考线 1.44** |
| seed 0 | 70.71 | 较好的种子 |

配对检验(140 局):

| 比较 | 净 | 95% CI | p |
|---|---:|---|---|
| **soup − base** | **+12.14 pp** | [+4.60, +19.68] | **0.0023** |
| soup − seed 0(较好) | −2.86 pp | [−7.71, +1.99] | 0.388 |
| **soup − seed 1(较差)** | **+5.71 pp** | [+1.29, +10.14] | **0.021** |

**我预注册的判据是"落在两种子之间 = 中性",结果正是如此;但我同时预测它"很可能低于两者",这一预测被推翻了。**
在余弦仅 +0.02 的情况下,平均**没有**破坏性能。

**为什么有用**:soup **与较好的种子无显著差异**(p=0.39),却**显著优于较差的种子**(p=0.021)。
而我们已经证明**训练损失无法告诉你哪个种子好**(§0 第 3 条)。
因此实际收益是:**把"随机拿到 70.71 或 62.14(期望 66.42、极差 8.57)"变成"确定性地拿到 67.86"**——
用一次额外评测换掉种子风险,零额外训练。

### 5.1 soup 在做什么:保留共识,捡回一半分歧

| 两个种子的情况 | 局数 | soup 赢下 |
|---|---:|---|
| 都赢 | 84 | **83(98.8%)** |
| 只有 seed 0 赢 | 15 | 8(53.3%) |
| 只有 seed 1 赢 | 3 | 3(100%) |
| 都不赢 | 38 | **1(2.6%)** |

**soup 几乎完整保留两者的共识(98.8%),捡回约一半的分歧优势,但几乎不创造新能力(2.6%)。**
这说明各 ΔW 里真正有用的成分是**低维且共享的**,其余近正交的大部分是任务无关的方向;
平均把后者削弱了 √2 倍,却保住了前者。

### 5.2 一个必须排除的混淆,已在测

soup 的 ΔW 范数是单种子的 **0.7212 倍**(近正交向量求平均的必然结果)。
于是"soup 更稳"可能**根本不是平均的功劳,而只是更新幅度更小**。

**控制实验(作业 1033635,已提交)**:把 **seed 0 单独**缩放 0.7212 倍(alpha 32 → 23.08),
范数与 soup 相同但**没有做任何平均**。

| 控制组结果 | 判读 |
|---|---|
| ≈ 67.86 | **平均没有独立贡献**,真正起作用的是**缩小更新幅度**——那么 A2 应改写成"调小 alpha",更便宜 |
| 明显低于 67.86 | **平均确有独立贡献**,A2 成立 |
| 明显高于 67.86 | 更新幅度本身就调过头了,应直接标定 alpha |

这个控制只花约 10 分钟评测,**在把 soup 写进方案之前必须先跑**。

### 5.3 更新的谱结构:能力低维,方向随机

对 328 个 ΔW 里抽样 16 个做 SVD(零 GPU):

| 主成分 | 该成分能量占比 | 累计 |
|---|---:|---:|
| 1 | **50.55%** | 50.55% |
| 2 | 13.96% | 64.52% |
| 3 | 7.35% | 71.87% |
| 4 | 5.22% | **77.09%** |
| 8 | 2.45% | **90.06%** |
| 16 | 0.63% | 100% |

**单个主成分就占一半能量,前 4 个占 77%,前 8 个占 90%。rank 16 里真正被用到的大约只有 4–8 维。**

而两个种子的 rank-16 行空间**几乎互不相关**:平均平方重叠 **0.34%**,
而 15,360 维空间里两个随机 16 维子空间的期望重叠是 0.10% —— 仅高于随机 3 倍。

**把三件事放在一起,机制就完整了:**

| 空间 | 两个种子的关系 |
|---|---|
| **权重空间** | 近正交(余弦 +0.02),子空间几乎随机(重叠 0.34% vs 随机 0.10%) |
| **行为空间** | 高度重叠(140 局里 84 局同赢、38 局同输,一致率 87%) |
| **平均之后** | 保住共识(98.8%),削弱各自的特异方向 |

**即:同一套行为可以由许多互不相关的权重方向实现。**
监督量撑不起 6,556 万参数,于是每个种子随机挑一组方向去实现大致相同的行为;
平均两组方向仍然落在"行为良好"的区域,并把各自的特异成分削弱 √2 倍。

**这直接预测 r=4 不会掉多少分**(前 4 个成分已占 77% 能量),**同时应当显著缩小种子极差**
(可选方向从 16 维降到 4 维)。今晚 1033596/1033598 正是在测这个。

### 5.4 控制实验的结论:**A2 降级——起作用的是"缩小更新",不是"平均"**

作业 1033635(seed 0 单独缩放 0.7212,alpha 32→23.08,**不做任何平均**),7 分 11 秒,EM **66.43**。

| 模型 | EM | 对 base 的净效应 | p |
|---|---:|---:|---|
| base | 55.71 | — | — |
| seed 1(原始) | 62.14 | +6.43 | 0.122 |
| **shrink 0.72(seed 0)** | **66.43** | **+10.71** | **0.011** |
| **soup(s0+s1)** | **67.86** | **+12.14** | **0.0023** |
| seed 0(原始) | 70.71 | +15.00 | 3.2e-04 |

关键比较:

| 比较 | 净 | 95% CI | p |
|---|---:|---|---|
| **shrink(s0) − soup** | **−1.43 pp** | [−6.67, +3.81] | **0.79** |
| shrink(s0) − seed 0(原始) | −4.29 pp | [−9.89, +1.31] | 0.210 |

**按提交前写定的判据(\|Δ\| < 2.5 pp → "平均没有独立贡献"),结论是:A2 降级。**
soup 与"单纯把 seed 0 缩小到同样范数"**统计上无法区分**(p=0.79)。
soup 那 +12.14 pp 里,绝大部分由**更新幅度更小**解释,而不是由"多个种子平均"解释。

**实际影响很大**:如果起作用的是幅度,那就**不需要训第二个种子**——
改一个 alpha 即可,成本从"多一次完整训练(7.4 GPU 小时)"降到"零"。

**还差最后一块拼图(作业 1033684,已提交)**:把同样的 0.7212 缩放施加到**较差的 seed 1** 上。

| shrink(s1) 的结果 | 判读 |
|---|---|
| 与 shrink(s0)=66.43 接近(极差 < 4 pp) | **缩放是方差消除器**:无论拿到哪个种子,缩放后都落到约 66 —— 这才是真正可推广的便宜手段 |
| 仍然明显低于 66.43 | 缩放只是"把好种子往下拉",不能救差种子;那么它既非提升也非稳定手段,应整条放弃 |

**注意 shrink 让好种子变差了**(70.71 → 66.43,−4.29 pp,虽不显著)。
所以缩放**不是免费的提升**;它的价值只可能在"消除种子风险"上,而这取决于 1033684。

### 5.5 第二个控制组推翻了 §5.4:**缩放不是解释,A2 恢复(但价值有限)**

作业 1033687(把同样的 0.7212 缩放施加到较差的 **seed 1**),7 分 22 秒,EM **60.00**。

| 模型 | EM |
|---|---:|
| base | 55.71 |
| seed 1 | 62.14 |
| **shrink(seed 1)** | **60.00** |
| shrink(seed 0) | 66.43 |
| **soup(s0+s1)** | **67.86** |
| seed 0 | 70.71 |

| 汇总 | 均值 | 极差 |
|---|---:|---:|
| 原始两种子 | 66.43 | **8.57** |
| 缩放后两种子 | **63.21** | 6.43 |

| 比较 | 净 | p |
|---|---:|---|
| shrink(s0) − seed 0 | −4.29 | 0.210 |
| shrink(s1) − seed 1 | −2.14 | 0.549 |
| **soup − shrink(s1)** | **+7.86** | **0.0034** |
| soup − shrink(s0) | +1.43 | 0.791 |

**§5.4 的结论错了,现予撤回。** 当时我只对**运气好的那个种子**做了缩放控制,看到 66.43 ≈ soup 67.86 就下了
"平均没有独立贡献"的判断。补上第二个种子后,结论反过来:

1. **缩放把两个种子都拉低了**(−4.29 与 −2.14,方向一致),**均值从 66.43 降到 63.21**;
2. **缩放几乎不缩小种子极差**(8.57 → 6.43),**不是方差消除器**;
3. **soup 显著优于 shrink(s1)**(+7.86,p=0.0034),与 shrink(s0) 打平。

**所以:**
- **"调小 alpha"这条应当放弃**——它在两个种子上都掉分,且不稳定方差。
- **A2(soup)恢复,但价值要如实写**:它给出**确定性的 67.86**,略高于随机取一个种子的期望 66.43(+1.43),
  但**打不过运气好的那个种子**(−2.86,p=0.39)。**它买的是确定性,不是增益**,代价是多训 k−1 个种子。

**方法论教训(记在这里以免重犯)**:单臂控制组不足以下结论。
我在只有 shrink(s0) 时就把 A2 判为降级,并在 8 分钟后被 shrink(s1) 推翻。
**凡是"用更简单的机制解释掉一个效应"的控制,都必须在效应出现的整个范围上做,而不能只测一个点。**

### 5.6 把 soup 当探针用:剂量改变的是"可靠学到的那部分"的**符号**

既然精确平均会保留两个种子的**共享成分**、削弱各自的特异成分,
它就可以当成一台"提取共享成分"的探针。于是把同样的平均施加到**两个已崩塌的 39 步种子**上(作业 1033705):

| 剂量 | 两个种子 | 精确平均 | 对 base |
|---|---|---:|---:|
| 39 步 | 22.86 / 20.71 | **29.29** | **−26.43 pp(p=2.5e-08)** |
| 154 步 | 70.71 / 62.14 | **67.86** | **+12.14 pp(p=0.0023)** |

39 步的平均相对两个输入分别是 +6.43(p=0.108)与 +8.57(p=0.023),
跑满上限从 108/111 降到 99 —— **平均确实削掉了一部分特异损伤,但绝大部分崩塌原封不动地留了下来**。

**结论:崩塌位于共享子空间,不是种子噪声。**
换句话说,**剂量改变的不是方差,而是"两个种子都可靠学到的那部分"的符号**:

- **39 步时,可靠学到的东西是有害的**(平均之后仍比 base 低 26 个点);
- **154 步时,可靠学到的东西是有益的**(平均之后比 base 高 12 个点)。

这解释了为什么"训练不足比不训练更糟"是稳固结论(§17 双种子确认),
也解释了为什么在崩塌带里换种子、换初始化、做平均都救不回来——**要救只能改剂量**。

**对方案的影响**:A4(按 rollout 选剂量)从"规程建议"升级为**必须项**。
在崩塌带内的任何其他优化(A1 降秩、A2 平均、A3 决策加权)都只是在负值上做微调。
