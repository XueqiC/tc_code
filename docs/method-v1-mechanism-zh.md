# 方法 v1 完整机理(实现级白话,数值与公式对齐代码)

设定:support set S = k 条 query(默认 k=50,劈成 35 fit + 15 cal)+
单个按 token 计费 black-box teacher(deepseek-v4-pro)+ 开源学生
(Qwen3.5-2B,LoRA r=16)+ 预算 b(默认 20k response tokens)。

## ① 学什么:从梯度里提取技能坐标系

对每条 support query 及其 teacher 演示,做一次 teacher-forced
前向+反传(不更新参数),收集 96 个 LoRA-B 模块的梯度,经 Adam
预条件化后随机投影到固定维度,单位化 —— 这就是"这条例子会教学生
什么"的指纹。分两个视角存:**响应视角**(对回答 token 的梯度,
含"怎么做"的信息)和 **prompt 视角**(只看题面)。

把 50 条响应视角指纹喂给稀疏字典学习
(MiniBatchDictionaryLearning, n_components=min(64, 语料行数/2),
lasso 系数 α=0.05):字典的每个基方向 = 一个 capability atom。
选 L1 而非 PCA 的原因是可辨识性(旋转不变性会让"技能"没有唯一
定义;E1 上 L1 域内技能分离 AUROC 0.906 vs 稠密子空间 0.615)。

**任务需求** w = 50 条 spec 码(绝对值)的均值,归一化;
**每技能配额** = w · b。直观:这个任务由哪些技能构成、各占几成,
预算就按几成切。

## ② 怎么买:逐轮采购 + 桥预测 + 环内验货门

每轮:
1. **字典重拟**:在 spec + 已购全部行上重拟字典(atoms 随购买增多
   而变细),重算需求账本 ledger。
2. **汇率校准** κ = 已知 on-task 例子的平均码质量(code mass)——
   "一条正常例子值多少码"。供给码一律用**原始幅度**除以 κ,绝不
   归一化(lasso 码弱 = 例子真的不相关,归一化会伪造供给,这是
   97% 浪费事故的根因之一)。
3. **桥预测**:买之前只能看到候选题面。用已付费的 (prompt特征,
   响应特征) 对拟合核岭回归(对偶形式 M=(K+λI)⁻¹R,
   λ=0.1·tr(K)/n),预测候选的响应特征,再过字典得到预测供给码 ŝ(x)。
4. **买谁**:效用 u(x) = Σ_a min(配额余量_a, ŝ_a(x)·t̂) / t̂
   (t̂=已购行平均 token 数)。按 u 降序买,批内逐单扣减工作账本
   (防止一批近重复例子重复计分),每轮 ≤8 单,买满预算为止。
5. **验货**(环内,关键):回货过两道门 —— (a) 执行检查:代码真的
   跑得通;(b) prompt 离群门:题面在梯度空间对 spec 子空间的
   残差分数 ≥ 15 条 cal query 里最差那条(宽门,只拒离群)。
   被拒的钱**不沉没**:富余阶段把余款花给"过门且码密度最高"的
   候选。→ 这道门是纯度机制本体:同一批购单,有门残留 0.000,
   去门 0.900(sqljoin@2B×20k,已在 b=2k/10k/20k/40k × 3 种子闭环)。

## ③ 怎么学:等算力 SFT + 每技能损失曲线

全部购得演示做 plain SFT:epochs = min(8, max(3, round(3b/实购tokens)))
(小语料自动多跑),lr 2e-4,梯度累积 8。**不做需求加权**(判定:
在已验证 on-task 的语料上加权无增益,纯度已由采购门保证)。

每行在入选时打上主技能标签(argmax 码),训练中把每行损失计入
其技能 → **每技能损失曲线**免费得到。定义"滞后技能":后 1/3 步的
平均损失 > 前 1/3 的 50%。多数技能两个 epoch 内吸收完,滞后集
因种子而异(如 [13] 或 [5,12,41,45])。行为探针每 8 步测 15 条
cal 的可运行率,留最优 checkpoint(大预算档关掉,已知代价 .889
vs .957)。

## ④ 怎么补:学生在环的技能级纠错(ourscorr)

1. 先花 b/2 买种子语料(~100-120 行),训中间学生。
2. 找缺口,两个变体:
   - **rollout 版**:中间学生对种子题作答,执行检查判对错;错题的
     响应码取平均 = 缺口方向。
   - **免 rollout 版**:直接读 ③ 的损失曲线,滞后技能上的 spec
     需求 = 缺口方向(两版精度等效 .618 vs .633,后者省一整轮生成)。
3. 剩余 b/2 按 桥预测码·缺口 排序买,买满为止;全量重训终版。
与 LLM2LLM 的唯一差异是缺口在技能空间而非错题实例空间 → 同预算
买到多 ~20% 互异行(74 vs 89 tok/行),方差减半(.03 vs .08)。

## ⑤ 怎么不越界:conformal 证书

35 条 fit 拟合梯度子空间(90% 能量),15 条 cal 得分排序取
分位数 → conformal 边界(α=0.10);部署时每个请求打分,界内保证
覆盖(Clopper-Pearson 两侧界),界外可拒。

## 一句话机理
同一套技能坐标系贯穿全程:需求用它记账、采购用它定向、验货用它
把门、训练用它观测、纠错用它命名、边界用它划定 —— 每个买来的
token 都花在被点名的技能上,所以预算浪费 2-4%、界外残留 0、
in-task 与最强 baseline 并列。

  计费抽取(模拟计费协议);AppWorld 段将是真实 API 计费。
- in-task 上所有合理方法在 2B×20k gsm 挤在同一水平带(外部 200 题
  .60-.66);方法的差异化主张是纯度/证书/预算效率/纠错机制,
  不是裸准确率。
