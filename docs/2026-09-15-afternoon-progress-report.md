## 2. 控制器升级(已实现、已合并主干 5bad4eb)

默认仍是严格逐 token 蒸馏 p_i = n_i / Σ n_j。两步:

1. **有限幅度候选**:v = argmax_{w∈Δ} ûᵀ(w − p) s.t. KL(w‖p) ≤ ρ,由 w_i(β) ∝ p_i exp(û_i/β) 上的一维 β 搜索得到;
   ρ 是声明的预算(默认 0.05,同时报 0.01 / 0.2)。
2. **幅度控制**:w(α) = (1−α)p + αv,α* = argmax_{0≤α≤α_max} [α(ĝ − κσ̂) − (c/2)α²],ĝ、σ̂ 来自**独立的另一半反馈**;
   α* = 0 是一等结果("no reliable reallocation; default distillation")。

反馈设计:固定非零温度(score-function 梯度用同一温度)、均匀或"信息量"采样(两次筛查 rollout/父任务后按 q(j)=½μ(j)+½s_j/Σs
分配,记录并应用 μ/q 权重,上界 2)、筛查样本不用于收益估计、总量上限 64。新臂 TR / TRPERM;MECH/PERM 保留为 legacy。

**在旧证据上的表现**(react7 银行 922 段,昨夜饿死的 v1 反馈;零新调用):

| 方向 | α* | ρ | β* | 有效片段数 | 结论 |
|---|---|---|---|---|---|
| A→B | 0 | 0.05 | 57.9 | 782 | 默认蒸馏 |
| B→A | 0.0028 | 0.05 | 113.1 | 782 | 极小幅再分配 |
| pooled | 0 | 0.05 | — | 782 | 默认蒸馏 |

与旧 softmax(β=0.01,w_max = 1,单片段)对比:同样的证据下,新控制器既不塌缩,也不押注。
文件:`results/cr_diagnostics/controller_reuse_r7_s200_ball/controller_analysis.json`;文档 `docs/hotpotqa_weight_controller.md`。

读法:
- AdamW 在零动量处近似符号映射,其一阶导数与真实一步更新几乎正交(余弦 ≤ 0.25),量级差 8–9 个数量级或反向到 0.01;
  沿信任域方向连加权损失变化的**符号**都预测反了。3 步外推更差。
- 唯一被预测对的是"加权训练损失随 α 线性下降"——这是重加权的定义性后果,不是学习收益。
- 留出 CE 的真实变化 ≤ 0.004 nats(1.0 时 +0.017),预测为 0:片段权重变化对留出损失几乎没有一阶效应。
- 因此 u_i = hᵀ ∂Θ/∂w_i(昨夜的"actual AdamW first step"映射)不是可执行的收益代理;控制器的 ĝ 也不能建立在它上面。
  这印证了你的判断("局部导数正确并不保证大幅重分配后的更新接近线性预测"),并且在小 α 就已不成立。
