## 1. "ours" 策展列为什么反而低(主要失败)

对比同一批采购下 plain vs ours 策展(mx 两种子):

| 格 | 行数 | 训练 token | 语料对 support 相似度 | 优化步 | exec |
|---|---|---|---|---|---|
| M_ours_plain (s0) | 168 | 19995 | .816 | 63 | **.933** |
| M_ours_ours (s0) | 136 | 18550 | .855 | 51 | .767 |
| M_ours_plain (s1) | 170 | 19992 | .809 | 66 | .833 |
| M_ours_ours (s1) | 132 | 18068 | .857 | 51 | .767 |

**机制诊断**:矩阵协议里策展发生在预算花完之后,门筛掉的 ~20% 行(7-9% token)是
**沉没成本,无法回购**;且被留下的语料对 support 的嵌入相似度系统性升高
(.81→.86)——门把多样性尾部剪掉了,语料更同质。两件事叠加:数据更少 + 更同质
→ in-task 下降。

**为什么综合臂(F_atom_boot3)不吃这个亏**:综合臂的门在**采购循环内**起作用
——拒收的货触发富余阶段回购,预算最终花满(无停版 .957±.02)。矩阵把门从采购
环节错位移植到策展环节,才产生损失。这与之前的实现级发现 #2(免费货架紧门选优、
付费采购宽门验货)同构:**门的正确位置取决于是否还有重新花钱的机会**。

**修复(今晚验证)**:策展列的 ours 改为"仅需求加权"(E3_CURATE_GATE=0),门保留
在采购臂内。重跑 M_selfinst_ours / M_ours_ours / M_ourscorr_ours × 2 seeds。

**保底口径**(若加权仍不加分,见 §3):策展段的主张收缩为"门的价值在边界纯度
(sqljoin 残留 0.000 vs .83-.87)与预算效率,不在 in-task 均值"。

## 2. 为什么 Self-Instruct 是最强 acquisition baseline

| 行 | 行数 | tok/行 | 预算花费 | exec (2 seeds) |
|---|---|---|---|---|
| selfinst | 181-184 | ~92 | 16.8k/20k (84%) | .883±.05 |
| evol | 70 | 147 | **10.3k/20k (51%)** | .667±.03 |
| llm2llm | 222-229 | ~89 | 20k (100%) | .817±.08 |
| ourscorr | 269-270 | ~74 | 20k (100%) | .867±.03 |
| ours | 168-170 | ~118 | 20k (100%) | .883±.05 |

- **Self-Instruct 的设计优势 = 广度优先 + 验证过滤 + 短样本**:多样种子指令、每行
  只 ~92 token,同预算下买到最多的**互异**on-task 样本;exec 检查保证正确性下限。
  在干净 few-shot 设定里,学生缺的正是覆盖面,广度直接变现。
  它的弱点不在 in-task,而在**无边界控制**(纯度任务上无引导采购的残留 .83-.87)
  和**无预算意识**(只花了 84%,也不知道该把 token 花在哪个技能上)。
- **Evol-Instruct 垫底的一半是我们的实现问题**:官方多轮进化,我们只跑了 1 轮
  ×2 分支,验证通过仅 70 变体 → **预算只花出去一半**;另一半是设计本身:难度
  进化使样本偏离 support 分布(147 tok/行,难度↑),对 2B 学生 + 小预算是
  distribution shift。**公平性修复已在跑**:按官方口径扩分支(--per-query 4),
  扩完后 evol 行整行 3 种子重跑(独立池文件,不污染现有表)。
- **LLM2LLM vs ourscorr(蒸馏侧对决的机制)**:两者唯一差异是增购导向。LLM2LLM
  对**错题实例**做变体 → 样本冗余(围着难例转)、方差大(.08);ourscorr 把失败
  过字典投影成**技能缺口方向**再买 → 每 token 买到更多互异样本(74 vs 89 tok/行,
  270 vs 226 行),均值高(.867 vs .817)且方差小(.03)。这正是"atom 词汇驱动
  学习"的直接证据格。

## 3. 蒸馏/策展侧横评(为什么 plain 这么强)

所有 acquisition 臂的产出都过了执行检查,语料正确性下限已经很高,策展的
"去噪"空间天然小:
- **AlpaGasus**:teacher 打分 94% 给 5.0(grade inflation,写进论文),过滤只
  砍掉明显残次 + 缩小数据量,效果在 plain 附近波动(.883±.05 vs .883±.05)。
  它设计上假设语料含大量低质(Alpaca 52k 场景),在"按需购买+验证"的设定下
  前提不成立。
- **LESS**:权重来自对 support 的梯度相似度;语料本来就是对着 support 买的,
  权重分布平,增益有限(.883±.02)。
- **我们的需求加权**:同理——在**已经 on-task 的语料**上,加权的边际价值低;
  它的判定场景是语料含边界外杂质时(sqljoin 门+权重把残留打到 0.000)。
  **结论候选**:策展段的贡献主张应绑定纯度/边界控制,而非 in-task 均值。

## 4. boot4(探针精化字典)为什么在 gsm 上无增益

boot4 = boot3 (.800=.800 seed1):k=50 的 support 对 gsm 覆盖已充分,LOO 方差挑出
的"低置信 atom"多是残差噪声原子,985 token 的探针买不来新信息。**boot4 的判定
实验应该是故意削弱 support(k-sweep / 偏斜子采样)**——支撑"少样本质量鲁棒性"
主张,列入排期,今晚不进 scope。

## 5. capability atom 设计本身的改进候选(记录,不进本次 scope)

1. **采购目标缺多样性项**:u(x)=Σmin(r,ŝ)/t̂ 只看技能供给,不看与已购样本的
   冗余 → 是 §1 同质化的源头之一。候选:u(x) 加边际增益/facility-location 项。
2. **字典规模拍脑袋**:n_components=min(64, k/2),可否由 reconstruction error
   的 elbow 或任务复杂度自适应。
3. **探针的目标函数**(boot4):当前只降"不确定性",可改为最大化 demand 估计的
   预期信息增益(主动学习口径,和 problem setting 的故事更一致)。
