## 0. 结论
**靶向练习(D)相对通用局部练习(C)没有可重复的净收益。** 首轮 D 领先 8 题,换一个训练种子后领先消失(R1 两种子 pooled D−C = 0);
把练习池从 22 条扩到 64 条、加上两侧条件覆盖与 multi_turn 快照重建之后,D 仍只领先 3 题(单种子),同样落在训练随机性之内。
两臂对 base 的平均提升约 +4~+6 题(+2 pp),也在噪声内。**局部层(held-out 练习)在七次评测里始终是 17–21/33,没有任何臂真正改变它**,
确认集(独立父任务、两侧条件配对)C/D 都只比 base 多 1 题。按用户 07:45 CDT 备忘的判定表,这属于"D 的优势在重复或扩展后消失 → 当作不稳定信号,不扩大叙事"。

## 1. 设计与实际执行
核心问题:同样的教师预算与训练暴露下,围绕学生诊断缺口生成的短练习(D)是否比通用局部练习(C)更能提升未见完整任务?
- 划分:support 24 题(5 seed rollout,19/24 成功 → 5 个失败 seed 诊断)、calibration 16 题、评测子集 256 题(分层)。
  第 3 层排除 web_search 10 题(项目无 SERPAPI key,所有模型恒 0;官方 checker 也不认裸类别)→ **246 题**。
- 训练前登记的缺口:seed_0/3 archival 检索(memory_kv,notetaker/healthcare 场景)、seed_2 并行调用单位(live_parallel)、
  seed_1/4 多轮前置条件与收尾(multi_turn)。
- 练习方向:`condition`(关键条件变→正确行为变,并校验确实变了)、`surface`(表面变→决策不变)、`neighbour_correct`(邻近正常情境→保留原本正确的行为)。
- R1:每臂 22 条(两条 multi_turn 诊断 0 条,执行器快照不可用);R2:保留 R1 的 22 条 + 两侧覆盖 + 按正确行为去重 + multi_turn 快照重建(重放前几轮 ground-truth 调用),
  得到 C 63 条(触 24k 共同输出上限,实花 21.0k token)、D 64 条(9.7k token)。
- 训练(两臂完全一致):LoRA r16/α32,AdamW lr 1e-4,512 监督 token/步,目标 = 0.5 teacher one-hot + 0.5 冻结 base 全词表;
  总监督 token ≈15.9k(R1:611/pass × 26 pass = 52 步;R2:1,585/pass × 10 pass = 40 步,另存中点 checkpoint)。
  注:方案原定"单 pass、lr 1e-5"在 BFCL 上只有 611 监督 token / 2 步,等于没训练,故按 ≤16k 上限调整剂量并已告知。
- 评测:贪心(T=0.001,top-k 1);base 重复评测 246 题只翻 1 题,评测噪声可忽略。
- 教师花费:R1 诊断+练习 ~9.3k 输出 token,R2 练习 30.7k,确认集少量,合计 < $2。GPU3 约 20 小时。

## 3. 判断(对照方案第 9 节判定表)
1. **"D 的优势在重复后消失"**:R1 pooled D−C = 0,成立。R2 单种子 +3 题、CI 跨 0,不足以翻案。→ 不稳定信号。
2. **"全任务小幅改善、局部始终不变"**:两臂对 base 都有 +4~+6 题,但 held-out 七次不动、确认集只 +1。
   不能宣称"补上了局部缺口再迁移回完整任务";更像十几个 token 决策的重排在 246 题上的随机涨落。
3. **64 条 vs 22 条**:C 从 165(R1 两种子均值)到 164.5(R2 两种子均值),**多样性本身没有带来收益**;D 从 165 到 168(单种子),仍在噪声内。
4. 干预量级是根因:≤16k 监督 token、base 已对 96% 的前提下,LoRA 只能改十几个决策,与该子集 ±8 题的种子波动同量级。

## 4. 训练不稳定:R2 D 种子 1 塌缩(2026-09-12 15:12 CDT 观察)
同一批 64 条练习、同一剂量,仅换训练种子,D 的 adapter **退化为重复输出**:在 multi_turn 任务上反复发同一个工具调用直到 4096 token 上限
(例:连续重复 `get_stock_info{symbol:"NVDA"}`),单条耗时从 1.4 秒涨到 100–190 秒,评测被拖长数小时。其训练 loss 收到 0.0003(C 为 0.034)。
这说明 **15.9k 监督 token / lr 1e-4 / 40 步这个配置对 64 条短练习已经过量**,臂间差异被训练不稳定性支配。评测跑完后数字补入 §2.1。

## 5. 建议
1. **机制线收口**,记为"未确立"。GPU3 回主线(选择性替换 D3 vs D2 的 BFCL 实验)。
2. 如果还要再试一次,只推荐一个便宜且直击根因的变体:**只监督决策 span**——去掉 base 已确定的语法 token,把预算全部花在那 ~4% 的决策位置上,两臂同做、每臂两个种子。
   其余(完整轨迹 A 臂、原位置指导 B 臂、换 benchmark)不建议,因为它们都不改变"能改的决策只有十几个"这个瓶颈。
3. 可写进论文的收获有两条,都与主线相关:
   - **干预量级分析**(§2.4):在 few-shot + 预算受限的黑箱蒸馏里,监督 token 的绝大多数落在学生已经正确的位置上,这正是我们"按学习回报选择替换目标"的动机。
   - **评估协议**(§3、§4):246 题子集上单种子差异 ±8 题、且训练可能塌缩,因此任何臂间比较至少要两个训练种子;同样的教训在基线曲线上复现了
     (SAD 在训练数据完全相同的两格上 60.7 vs 54.3)。
