# 交互蒸馏提案的最快验证 — 实验与分析报告
2026-09-14 00:45 CDT。对象:`docs/TC_Interaction_Distillation_Design_20260913.md`。
性质:**仪器与可构造性检查**,按该文档 §11.2 执行;**不是训练结果**,不替代已冻结的 I/P/L。
本轮**零教师调用、零教师花费**(预算仍为已花 14,058 token / $0.084,剩 15,942 / $4.92)。

---

## 1. 为什么先做这一步
提案的核心算子是四格交互
`B = ℓ11 + ℓ22 − ℓ12 − ℓ21`,训练目标 D2 需要标签 `t_e = 1`(正确绑定优于交换绑定)。
**如果这个量在我们的数据上不可测、或标签拿不到,D0/D1/D2 三臂训练就没有意义。**
这一步只做打分与少量梯度,**不训练**,因此用一张卡约 15 分钟就能定论,
而不是再押一两个小时的训练。

## 2. 做了什么
从 24 条已恢复的教师链构造关系对,每对含两个合法状态 `s1/s2` 与各自的正确后续 `y1/y2`,
四格全打,**两种打分并列**:
- **full-turn**:整个 assistant turn 的 log probability;
- **action-only**:只累加 Action 与终止 token,**排除 Thought token**,但两状态用**同一段完整候选前缀**。

数值纪律(按文档 §8.4 写死):**四个梯度先做带符号求和,再做统一预条件与 sketch**,
**不允许各自单位归一化后再相减**;差分与内积**FP32 累积**。
交叉项**只用于打分**,**不冒充执行历史**;**未改动任何 Wikipedia 事实**。

作业 `1020206`,约 15 分钟,峰值显存实测见 §6。

## 3. 结果一:B 完全可测,但正确绑定**不占优**

| | full-turn | action-only |
|---|---|---|
| 与 0 不可区分 | **0 / 12 = 0.0%** | **0 / 12 = 0.0%** |
| B 中位数 | −6.32 | −13.85 |
| B 范围 | −55.18 … +16.92 | −20.83 … +12.24 |
| matched beats swapped | **4 / 12** | **3 / 12** |
| 经核验的排他绑定 | **0** | **0** |

**两点必须一起读**:
1. **B 在数值上完全可测**——没有任何一对落进"与 0 不可区分"(阈值 full 0.083 / action 0.018,τ=1.0)。**仪器没问题。**
2. **但正确绑定赢的比例是 4/12 与 3/12,低于随机的 6/12**;
   并且**经核验的排他绑定为 0**,报告自己写明:
   **在没有排他性核验的情况下,这些比例不能称作"绑定准确率"**。

## 4. 结果二:根因是结构性的——我们能造的不是提案要的那种关系
可构造 **24/24**,选中 12 个不同父任务,**但全部 24 对标记 `cross_validity_unknown`**。

看它们实际是什么:12 对**全是 progress 对**——**同一任务的连续两步**,
第 k 步候选是 `search[X]`,第 k+1 步候选是 `finish[答案]`。例如:

| 父任务 | 两步 / 两个候选 |
|---|---|
| 5a8f46b1… | [3,4]:`search[Indianapolis 500]` ; `finish[Memorial Day weekend]` |
| 5ab708da… | [2,3]:`search[William G. Dever]` ; `finish[November 27, 1933]` |
| 5ab67b57… | [2,3]:`search[Carvedilol]` ; `finish[Coreg]` |

而文档 §6 要的是**目标对调的对称关系**(已知 A 的年份 → 去查 B;已知 B 的年份 → 去查 A)。

**progress 对的交叉项天然"可能仍然正确"**:
- 检索**之前**直接 `finish[答案]` —— 模型本来就可能知道答案,这不是错;
- 检索**之后**再 `search[X]` —— 只是冗余,也不是错。

**所以排他性一个都核验不出来。** 这不是算子的问题,是**素材构造**的问题。

## 5. 结果三:Thought 文字匹配的捷径**实测存在**
full-turn 与 action-only 的 B **在 12 对中有 5 对符号相反**:

| 关系 | B(full) | B(action) |
|---|---:|---:|
| 5ab67b57…:2-3 | **−55.18** | **+12.24** |
| 5abdd8c5…:2-3 | **+16.92** | **−20.83** |
| 5ab45d2e…:2-3 | +5.38 | −19.15 |
| 5a7bdef4…:2-3 | +8.63 | −14.15 |
| 5ab708da…:2-3 | −5.42 | +0.17 |

**符号相反意味着两种打分在"哪一种绑定更好"上给出相反答案。**
这正是文档 §7.2 预判的捷径:Thought 若复述题目实体,完整 turn 的匹配概率会靠文字对应虚高。
**这条实测证据支持"交互评分应聚焦执行部分"这个设计选择**;
但同样按 §7.2 的口径:**这只说明排除了 Thought 复述这一条捷径,不能宣称消除了全部捷径。**

## 6. 附带解掉的悬案:显存
本次实测 **峰值显存 25.59 GiB(reserved 25.95)/ 79.25 GiB**。

回顾这条线今天的经过:
1. 六格数组 `1020028` 全部 CUDA OOM,各约 1h53m,**≈11 GPU·h 无产出**;
2. 第一次修复:释放与下一次 backward 重叠的 source gradient 及四组陈旧张量
   —— CPU 夹具峰值 −11.19%,**六个 arm/seed 夹具上对角线与更新逐位相同**;但**这不是峰值大头**;
3. 第二次修复:**LM head 与交叉熵按 32 个位置分块**,词表工作区从
   一份全序列 BF16 logits 的 **614–659 MiB 降到 80 MiB(前向)/ 112 MiB(反向)**;
   数值上**数学等价而非逐位相同**(每 token `atol=2e-5`),**剂量字节级未变**;
4. **本次实测证明确实够用**:25.59 / 79.25 GiB,余量充足。

**结论:卡住 I/P/L 的 OOM 已解决,六个 adapter 随时可恢复,不会再因显存挂掉。**

## 7. 这一步决定了什么

| 观测 | 结论 |
|---|---|
| B 可测(0% 不可区分) | **算子本身可计算,仪器成立** |
| matched 仅 4/12、3/12,且排他核验 = 0 | **D2 当前没有可用的监督信号**(拿不到 `t_e=1`) |
| 12 对全是 progress 对 | **问题在素材构造,不在算子** |
| full/action 符号 5/12 相反 | **完整 turn 交互被 Thought 文字污染**,支持 action-only 评分 |
| 峰值 25.59 GiB | **I/P/L 的显存障碍已排除** |

**明确不能做的事**:硬给未核验的交叉项贴 `t_e=1`。那等于把"不知道对不对"当成"错",
正是文档 §6 禁止的;由此得到的任何 D2 优势都只能证明"错误标签有害"。

## 8. 下一步的两个选项(均不花教师预算)
1. **恢复六个 I/P/L adapter**:显存已证明够用;它回答的是**教学上下文组织**的价值,
   与本提案独立(文档 §11.1 明确 I/P/L 不因本提案改动)。
2. **检验"目标对调关系"能否构造**:从 200 题池里找**比较类**问题
   (A 与 B 谁更早 / 更高 / 更长),它们天然具备对称的两侧;
   若能构造并核验排他性,D2 才有监督信号。

两件可并行:前者用 GPU,后者主要是离线构造与核验。
