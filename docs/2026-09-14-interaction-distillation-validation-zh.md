# 交互蒸馏提案的最快验证 — 实验与分析报告
2026-09-14 00:45 CDT。对象:`docs/TC_Interaction_Distillation_Design_20260913.md`。
性质:**仪器与可构造性检查**,按该文档 §11.2 执行;**不是训练结果**,不替代已冻结的 I/P/L。
本轮**零教师调用、零教师花费**(预算仍为已花 14,058 token / $0.084,剩 15,942 / $4.92)。

---

## 1. 为什么先做这一步
提案的核心算子是四格交互
`B = ℓ11 + ℓ22 − ℓ12 − ℓ21`,训练目标 D2 需要标签 `t_e = 1`(正确绑定优于交换绑定)。
**如果这个量在我们的数据上不可测、或标签拿不到,D0/D1/D2 三臂训练就没有意义。**
这一步只做打分与少量梯度,**不训练**,因此用一张卡约 15 分钟就能定论,
而不是再押一两个小时的训练。

## 2. 做了什么
从 24 条已恢复的教师链构造关系对,每对含两个合法状态 `s1/s2` 与各自的正确后续 `y1/y2`,
四格全打,**两种打分并列**:
- **full-turn**:整个 assistant turn 的 log probability;
- **action-only**:只累加 Action 与终止 token,**排除 Thought token**,但两状态用**同一段完整候选前缀**。

数值纪律(按文档 §8.4 写死):**四个梯度先做带符号求和,再做统一预条件与 sketch**,
**不允许各自单位归一化后再相减**;差分与内积**FP32 累积**。
交叉项**只用于打分**,**不冒充执行历史**;**未改动任何 Wikipedia 事实**。

作业 `1020206`,约 15 分钟,峰值显存实测见 §6。

## 3. 结果一:B 完全可测,但正确绑定**不占优**

| | full-turn | action-only |
|---|---|---|
| 与 0 不可区分 | **0 / 12 = 0.0%** | **0 / 12 = 0.0%** |
| B 中位数 | −6.32 | −13.85 |
| B 范围 | −55.18 … +16.92 | −20.83 … +12.24 |
| matched beats swapped | **4 / 12** | **3 / 12** |
| 经核验的排他绑定 | **0** | **0** |

**两点必须一起读**:
1. **B 在数值上完全可测**——没有任何一对落进"与 0 不可区分"(阈值 full 0.083 / action 0.018,τ=1.0)。**仪器没问题。**
2. **但正确绑定赢的比例是 4/12 与 3/12,低于随机的 6/12**;
   并且**经核验的排他绑定为 0**,报告自己写明:
   **在没有排他性核验的情况下,这些比例不能称作"绑定准确率"**。

## 4. 结果二:根因是结构性的——我们能造的不是提案要的那种关系
可构造 **24/24**,选中 12 个不同父任务,**但全部 24 对标记 `cross_validity_unknown`**。

看它们实际是什么:12 对**全是 progress 对**——**同一任务的连续两步**,
第 k 步候选是 `search[X]`,第 k+1 步候选是 `finish[答案]`。例如:

| 父任务 | 两步 / 两个候选 |
|---|---|
| 5a8f46b1… | [3,4]:`search[Indianapolis 500]` ; `finish[Memorial Day weekend]` |
| 5ab708da… | [2,3]:`search[William G. Dever]` ; `finish[November 27, 1933]` |
| 5ab67b57… | [2,3]:`search[Carvedilol]` ; `finish[Coreg]` |

而文档 §6 要的是**目标对调的对称关系**(已知 A 的年份 → 去查 B;已知 B 的年份 → 去查 A)。
**但评审已修正这一点:目标对调本身也不自动解决问题**——交换之后仍可能只是重复查询已知信息,
**对称不等于排他**。真正需要的是:**在原有任务目标下,有依据判断正确 assignment 优于交换 assignment**
(例如一种分配产生错误答案、另一种能完成任务)。若两种分配都能成功、只是步骤多寡之差,
而我们的目标**没有步骤成本**,则**不得临时添加惩罚来制造标签**。

**progress 对的交叉项天然"可能仍然正确"**:
- 检索**之前**直接 `finish[答案]` —— 模型本来就可能知道答案,这不是错;
- 检索**之后**再 `search[X]` —— 只是冗余,也不是错。

**所以排他性一个都核验不出来。** 这不是算子的问题,是**素材构造**的问题。

## 5. 结果三:Thought 文字匹配的捷径**实测存在**
full-turn 与 action-only 的 B **在 12 对中有 5 对符号相反**:

| 关系 | B(full) | B(action) |
|---|---:|---:|
| 5ab67b57…:2-3 | **−55.18** | **+12.24** |
| 5abdd8c5…:2-3 | **+16.92** | **−20.83** |
| 5ab45d2e…:2-3 | +5.38 | −19.15 |
| 5a7bdef4…:2-3 | +8.63 | −14.15 |
| 5ab708da…:2-3 | −5.42 | +0.17 |

**符号相反意味着两种打分在"哪一种绑定更好"上给出相反答案。**
这正是文档 §7.2 预判的捷径:Thought 若复述题目实体,完整 turn 的匹配概率会靠文字对应虚高。
### 5.1 这条证据必须降一级解释(按评审)
由于 full-turn 恰好由两部分组成,有 `B_full = B_Thought + B_Action`。
**符号反转只说明 Thought 部分足以改变总体排序**,但原因至少有三种,本轮无法区分:
(a) 复述实体产生文字匹配;(b) Thought 的计划或事实内容**确实**与某个状态更相容;
(c) 长度、表达方式与条件概率差异。

**更关键**:`action-only` **仍然条件化于候选 Thought**——它移除的是 Thought token 的**直接计分**,
**没有**移除 Thought 对 Action 概率的影响。

**因此可写**:优先使用 action-only,以**避免完整 Thought 分数主导执行关系的衡量**。
**不可写**:"已排除 Thought 文字污染"。同时必须**保留两侧各自的行动边际**,
防止一个大的正边际掩盖另一侧仍然错误。

## 6. 附带解掉的悬案:显存
本次实测 **峰值显存 25.59 GiB(reserved 25.95)/ 79.25 GiB**。

回顾这条线今天的经过:
1. 六格数组 `1020028` 全部 CUDA OOM,各约 1h53m,**≈11 GPU·h 无产出**;
2. 第一次修复:释放与下一次 backward 重叠的 source gradient 及四组陈旧张量
   —— CPU 夹具峰值 −11.19%,**六个 arm/seed 夹具上对角线与更新逐位相同**;但**这不是峰值大头**;
3. 第二次修复:**LM head 与交叉熵按 32 个位置分块**,词表工作区从
   一份全序列 BF16 logits 的 **614–659 MiB 降到 80 MiB(前向)/ 112 MiB(反向)**;
   数值上**数学等价而非逐位相同**(每 token `atol=2e-5`),**剂量字节级未变**;
4. **本次实测证明确实够用**:25.59 / 79.25 GiB,余量充足。

**结论:卡住 I/P/L 的 OOM 已解决,六个 adapter 随时可恢复,不会再因显存挂掉。**

## 7. 这一步决定了什么(**已按评审逐条降级,见 §7.1**)

| 观测 | **可以支持的表述** |
|---|---|
| B 在 12 对上均非零 | **四格分数在已测样本上具有数值分辨力**;尚不代表监督标签或评分含义成立 |
| matched 4/12、3/12 | **没有有效绑定标签,也没有 50% 随机基准,因此不能与"随机"比较** |
| 12 对全是 progress 对 | **当前素材无法支持预定监督**;**算子的有效性仍未检验** |
| full/action 符号 5/12 相反 | **B 对评分组成敏感**;**尚未证明差异来自文字捷径** |
| 峰值 25.59 GiB | **当前工作负载的显存问题已缓解**;**完整训练仍需一次实际预检** |

### 7.1 我在上一版报告里说过头的地方(全部撤回)
1. ~~"4/12、3/12 低于随机 6/12"~~ —— **这是我的错误**:没有有效标签就**没有 50% 的随机基准**,
   这个比较不成立。
2. ~~"仪器没问题 / 算子成立"~~ —— 只证明**数值可分辨**,**算子有效性未检验**。
3. ~~"问题在素材,不在算子"~~ —— 只能说**当前素材不支持预定监督**。
4. ~~"Thought 文字捷径实测存在"~~ —— 见 §5.1 的降级。
5. ~~"I/P/L 不会再因显存挂掉"~~ —— 25.59 GiB 来自**打分与少量梯度**,
   **不能替代完整训练路径**(优化器状态分配、参考 KL、梯度累积、最长允许输入)。

### 7.2 "排他核验 = 0" 必须拆成三类(按评审)
- **已核验:两种分配都有效**
- **已核验:存在明确偏好**
- **尚未核验:无法判断** ← **我们目前几乎全在这一类**

**因此不能写成"证明这些关系没有监督价值"。** 当前真正阻塞训练的是**标签未知**,
**不是 B 的正负**。

### 7.3 一条必须写死的采样纪律
**若将来标签成立,训练前 B 为负恰恰可能说明学生需要学这项对应关系。**
**不得**筛掉这些样本、只留 base 已偏好正确绑定的样本——那是按训练前得分挑关系,
会把结论变成同义反复。

**明确不能做的事**:硬给未核验的交叉项贴 `t_e=1`。那等于把"不知道对不对"当成"错",
正是文档 §6 禁止的;由此得到的任何 D2 优势都只能证明"错误标签有害"。

## 8. 素材的两种用途必须分开(按评审,重要)
**不要把所有教学材料都强行变成四格负例。**
- **有正确后续、但没有可靠交叉偏好的教学链** → 用于**完整正例学习与 I/P/L**;
- **有可靠条件偏好的关系对** → **额外**用于交互监督。

两者可共用同一训练目标,但**监督信息不同**。**不能因为拿不到关系标签就浪费已购买的正确链。**

**同时必须承认的风险**:若自然素材中可获得的关系标签很少,
**四格目标可能只适合作为辅助项,未必能担当整个方法的核心**。这是本轮开始暴露的实际风险,
后续要看**关系构造成本与覆盖范围**,而不只是证明公式可计算。

## 9. 下一步(范围保持小)
1. **恢复 I/P/L**:**先让一个作业走完真实训练预检**——覆盖优化器状态分配、参考 KL、
   梯度累积、允许的最长输入——**再恢复其余作业**。(已提交单格 `1021697`,挂显存看门狗。)
2. **先查现有 12 对的标签状态**,不再追加分数分析:区分"未核验"与"确实无偏好",
   **只用现有执行记录与原有验证器**,不为每对做大量完整 rollout。
3. **用少量比较题检查一种真正明确的条件变化**:真实证据给出 A、B 两个年份,
   分别问"谁更早"与"谁更晚",两个最终回答形成明确条件对应。
   **这只是关系目标的合格性检查**,不能据此宣称证明了多步交互教学。
4. **缺教师目标时少量补齐,不坚持全程零 API**:离线找到合法问题**不等于**已拥有其教师示范;
   **绝不能**把程序或参考答案推导出的另一侧答案**冒充已购买的教师输出**。
   需要时用剩余 **15,942 token** 取一小批有效关系,**不重买整个池**。

取得有效关系后再跑同数据的 D0/D1/D2:**不要求 base 的 B 已为正,不按训练前得分挑关系**,
只要求**标签与来源可靠**。

**对本轮的定性(评审原话)**:它**成功阻止了一次标签不成立的训练,但尚未验证或否定交互蒸馏**。
下一轮重点从"这个分数能否测出来"转到"**这种监督能否低成本、自然地获得**"。
