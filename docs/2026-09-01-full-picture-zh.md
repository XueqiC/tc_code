# TC-Alignment 全景(2026-09-01 晚)

## 一、问题与故事线(不变)

给定大 LLM agent 和 k=50 条 few-shot query(**k 固定,是规格**),蒸馏一个小
LLM,使其能力边界 C 对齐任务边界 T。**大故事线:预算被尽可能用来提升
in-task performance** —— off-task 的走向由耦合结构解释,不作为优化目标。

本周的核心修正(用户指出):few-shot 支撑集 ≠ 蒸馏训练集。**k 条 query 只
定义 T;训练数据靠生成,要多少有多少**。此前一切失败的根源是整条流水线在
50 个点上打转。

## 二、机制现状(两相 + 统一生成)

### 相一:画边界图(map)
- 每条 query 一个 Beta 后验;可疑度 = 失败率上置信界。
- 每轮对最可疑点三选一:**可信劣于平均 → 花 teacher 生成变体;区间跨在平均
  上 → 花免费 rollout 继续观测;否则 → 已解决**。
- 观测由决策驱动(区间不再跨平均、或一批观测落在后验预期内即"测无可测"),
  **无固定 rollout 次数**;对点生成到"后验不再移动"为止(信息饱和),不是到
  "学生做对"为止。平均按点算,防止重点调查自己抬高基准。
- **变体传递测试**是边界与噪声的判别器:原题错而变体全对 = 措辞噪声;变体
  也错 = 真能力缺口(live_parallel_multiple 即此类)。

### 相二:填数据(fill)—— 统一为一个生成器
**生成对象永远是 episode**:回合 =(用户话术,动作序列(可空),回话)。
- 单轮题 = 1 回合退化情形;拒绝 = 动作为空的单回合;静默轮 = 中途某回合动作
  为空;终止 = 最后一回合的回话。
- **judge 永远是 benchmark 自己的**:有状态 → 真后端整条执行 + 状态比对;
  无状态 → 独立求解复现 + 官方 AST checker(参数带多可接受值)。
- 验证失败 → 把 judge 意见喂回重写(3 次限额)。产出率:难点 17%→100%。
- 硬规则:失败样本保留并标记(产出率可见);计分类别零行 → 训练前报错;
  收尾/拒绝行为零 → 告警;teacher 造不出 → 标 infeasible。

### 边界的四类行为(全部由失败解剖发现,非设计时想到)
| 缺什么 | 症状 | 补后效果 |
|---|---|---|
| ① 该调用什么 | — | 一直有 |
| ② 怎么收尾 | 永不终止(BFCL MT 归零 = AppWorld 步数打满) | MT 4.17→16.67 |
| ③ 整题拒绝 | 什么都调用,Irrelevance 崩 | Irrel 12.50→75.17 |
| ④ 某轮不调用 | 每轮硬调用改坏状态(benchmark 12.4% 回合静默) | pool v9 已含,评测中 |

### 训练侧
- 权重 = (1−p̂) + preserve·p̂:**买缺口 + 显式保住已有**;preserve 取值由
  实验决定(bfclpres 三档在跑),不人为拍板。
- 训练配置硬要求:AW_MAX_PROMPT_TOKENS=4096 tail;97G 卡。

## 六、本周教训(已固化为规则)
七个"不报错的错"(memory 静默崩/作废 split/共享文件竞态/生成器空转/等待器
只盯成功/写死路径×2/无数据目录)—— 共同形状:**失败长得像成功**。对策:每个
环节配一个"没有产出即报错"的检查;监视必须覆盖失败态;大文件走分块推送;
proxy 永不当上报数。
